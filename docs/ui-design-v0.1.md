# Zipelo v0.1 화면 설계

이 문서는 v0.1 앱 화면의 배치, 문구, 색과 간격, 구현 수용 기준을 정한다. 구현은 frontend 담당이 하고, 이 문서는 구현 요청의 기준이다. 기준 화면은 이준영 님이 2026-11-12에 제공한 목록, 폴더 내부, ZIP 만들기 모달 시안 세 장이다.

## 1. 전제와 제약

- 처음 쓰는 사람이 설명 없이 "열기 후 풀기"와 "ZIP 만들기"를 끝낼 수 있어야 한다.
- 앱 화면은 eframe 기본 위젯과 Painter 아이콘을 쓴다. 운영체제 기본 파일 창용 rfd를 외부 라이브러리 예외로 사용한다. 기존 렌더러 폴백과 작업자 계약은 유지한다.
- 작업자 계약 revision 2는 바꾸지 않는다. 화면은 계약에 이미 있는 값만 보여 준다.
- 화면 시험은 tests/ 아래에만 둔다.
- 이 문서의 디자인은 v0.1 범위다. 다크 모드, 미리보기, 설정 화면은 범위 밖이다.

## 2. 새 시안의 적용 범위

기존 전체 경로 나열 목록을 폴더 단위 탐색으로 바꾸고, 상단 툴바와 경로 줄, 검색, 하단 상태 줄을 추가한다. ZIP 만들기는 시안의 모달로 구성한다. 파일과 폴더 및 저장 위치 선택은 운영체제 기본 대화창을 사용한다. 기존 완료 판정과 저장 경고 표시 규칙은 7.3을 유지한다.

## 3. 디자인 원칙

1. 주요 기능 네 개는 큰 아이콘과 글자가 있는 툴바에 모은다. 모달의 실행 버튼과 결과 화면의 다음 행동은 파란 주 버튼으로 구분한다.
2. 사용자가 고르는 것은 경로 문자열이 아니라 파일과 폴더다.
3. 정상일 때는 내부 상태를 숨긴다. 결과가 정상이 아닐 때(일부만 풀림, 저장 여부 불확실 등)는 숨기지 않고 쉬운 문장으로 알린다.
4. 오류 문구는 무엇이 잘못됐는지와 사용자가 할 수 있는 일을 함께 말한다.
5. 영어 약어와 내부 용어(작업자, 프로세스, 게시, 동기화)를 화면에 쓰지 않는다.

## 4. 디자인 토큰

라이트 테마 하나만 만든다. 글자 대비는 흰 배경 기준 4.5 대 1 이상이다.

색:

- 창 배경 #F7F8FA, 패널과 목록 배경 #FFFFFF, 줄무늬 행 #F3F5F8, 테두리 #D9DEE5
- 본문 글자 #1F2933, 보조 글자 #5B6673
- 주 버튼 배경 #2563EB(글자 흰색), 마우스를 올리면 #1D4ED8, 누르면 #1E40AF
- 선택한 행 #E8F0FE, 끌어 놓기 강조 배경 #EEF4FF
- 성공 #15803D, 경고 #B45309, 오류 #B91C1C. 알림 상자 배경은 각 색의 10퍼센트 농도로 쓴다.
- 아이콘 색: 폴더 #E0A526, 파일 #7B8794, 압축파일 #2563EB, 잠금 #B45309

글꼴(시스템 CJK 글꼴 그대로): 제목 22, 큰 안내 문구 20, 본문 15, 보조 13. 13보다 작은 글자는 쓰지 않는다.

간격은 8의 배수(8, 16, 24, 32)만 쓴다. 창 안쪽 여백 16, 패널 안쪽 여백 16, 행 높이 32, 모서리 둥글기는 버튼 6과 패널 8, 끌어 놓기 영역 12.

버튼:

- 주 버튼: 높이 40, 최소 너비 112, 파란 배경에 흰 글자, 굵게. 화면당 하나.
- 보조 버튼: 높이 36, 흰 배경, 테두리 #D9DEE5, 본문 글자.
- 위험 또는 취소 버튼: 보조 버튼 모양에 글자색만 오류색.
- 비활성 버튼: 투명도 40퍼센트. 마우스를 올리면 이유를 툴팁으로 보여 준다(예: "먼저 압축파일을 여세요").
- 키보드 초점: 2px 파란 윤곽선(#2563EB)을 모든 버튼, 입력칸, 체크박스에 그린다.

창: 기본 1060x720, 최소 760x540(현재 값 유지). 목록과 영역은 창 너비를 모두 쓴다.

## 5. 아이콘

외부 이미지 파일 없이 Painter로 그린다. 목록에는 16과 20 크기, 툴바에는 40 크기를 쓰고 선 두께는 크기에 맞춰 조정한다.

- 폴더: 둥근 사각형에 왼쪽 위 탭, 주황색
- 툴바: 열기는 폴더 윤곽, 압축하기는 파일과 더하기, 압축해제는 아래 화살표, 암호화는 잠금
- 파일: 오른쪽 위가 접힌 사각형
- 압축파일: 파일 모양에 가로 줄무늬 세 개
- 잠금: 둥근 사각형과 위쪽 반원
- 성공(원 안의 체크), 경고(삼각형 안의 느낌표), 오류(원 안의 가위표)
- 끌어 놓기 영역 대표 아이콘은 48 크기의 압축파일 아이콘 하나

## 6. 화면 상태별 배치

창 제목은 압축파일을 열었으면 "압축파일 전체 경로 — Zipelo", 열지 않았으면 "Zipelo"다. 상단 툴바에 [열기] [압축하기] [압축해제] [암호화]를 왼쪽부터 배치하며, 큰 아이콘 아래 글자를 붙인다. 작업 중에는 새 작업을 여는 툴바 버튼을 비활성화한다. 모달이 열려 있으면 배경 화면은 조작할 수 없다.

### 6.1 빈 화면

- 툴바 아래에 압축파일 끌어 놓기 영역과 "압축파일을 여기에 끌어 놓으세요", 지원 형식 안내를 보여 준다.
- [열기]는 운영체제 기본 파일 열기 창을 연다. 파일을 끌고 오면 영역을 강조하고 "놓으면 엽니다"를 보여 준다.
- [압축하기]와 [암호화]는 6.7 모달을 연다. 압축파일이 없으면 [압축해제]는 비활성이며 이유를 툴팁으로 알린다.
- 하단 상태 줄은 "0개 항목", "선택 0개"를 보여 준다.

### 6.2 압축파일 열림과 폴더 탐색

```
+--------------------------------------------------------------+
| 압축파일 전체 경로 — Zipelo                                  |
+--------------------------------------------------------------+
| [열기]       [압축하기]       [압축해제]       [암호화]       |
+--------------------------------------------------------------+
| [위로] 현재 경로 [/Install              ] [파일 찾기       ] |
+--------------------------------------------------------------+
| [ ] 이름                                   크기     암호     |
| [ ] (파일) cab1.cab                        94.9 MB           |
| [ ] (파일) cab2.cab                        98.6 MB           |
|                                                              |
+--------------------------------------------------------------+
| 2개 항목                                          선택 0개   |
+--------------------------------------------------------------+
```

- 툴바 아래 경로 줄은 [위로], "현재 경로" 표시칸, "파일 찾기" 검색칸 순서다. 현재 경로는 압축파일 내부 경로이며 루트는 `/`, 하위 폴더는 `/Install`처럼 표시한다. 운영체제 파일 경로 입력칸이 아니다.
- 목록은 현재 폴더 바로 아래 항목만 보여 준다. 폴더를 열면 하위 목록으로 이동하고 [위로]는 부모로 이동한다. 루트에서는 [위로]를 비활성화한다. 검색은 현재 폴더 안의 이름을 거르며 하위 폴더 전체를 검색하지 않는다.
- 폴더 항목이 따로 없는 압축파일도 파일 경로에서 가상 폴더를 구성한다. 가상 폴더는 탐색용이며 작업자 요청에 가짜 ID를 넣지 않는다.
- 열은 체크박스, 이름, 크기, 암호 순서다. 이름 앞에 폴더는 주황색 아이콘, 파일은 파일 아이콘을 둔다. 크기는 오른쪽 정렬, 암호가 있으면 잠금 아이콘과 "있음"을 표시한다. "형식"과 수정 날짜 열은 넣지 않는다.
- 목록은 창 너비와 남는 높이를 사용하며 세로 스크롤한다. 폴더 진입 동작과 체크 선택 동작을 구분한다.
- 폴더를 체크하면 해당 폴더와 모든 하위 실제 항목을 추출 대상으로 확장한다. 부모 폴더와 자식 항목을 함께 선택해도 실제 ID는 중복 없이 한 번만 보낸다. 명시적인 빈 폴더 ID도 포함한다. 완료 판정은 이 확정된 요청 ID 집합과 동일한 범위를 사용한다.
- 하단 상태 줄 왼쪽은 현재 표시 목록의 "N개 항목", 오른쪽은 "선택 N개"를 보여 준다. 화면에서 체크한 항목 수와 재귀 확장된 요청 ID 수를 혼동하지 않는다.
- [압축해제]는 6.8의 운영체제 기본 폴더 선택창을 연다. 기본 위치는 압축파일이 있는 폴더다. 선택 항목이 있으면 확장한 선택 범위를, 선택이 없으면 전체 압축파일을 대상으로 한다. 검색 결과나 현재 폴더만으로 추출 범위를 암묵적으로 줄이지 않는다.
- 풀 위치 선택을 확정한 뒤에만 요청을 보낸다. 취소하면 폴더 생성이나 추출을 시작하지 않는다. 앱이 새 출력 폴더를 만드는 경로는 Unix에서 umask와 무관하게 0700으로 생성한다. 기존 사용자 폴더 권한은 바꾸지 않는다.
- 폴더 생성에 실패하면 요청 없이 "풀 위치 폴더를 만들 수 없습니다. 접근 권한을 확인하세요"를 보여 주고 다시 폴더를 고르게 한다. 실패나 취소 뒤 앱이 이번 작업에서 만든 빈 폴더만 정리한다. 사용자 폴더와 비어 있지 않은 폴더는 지우지 않는다.
- 충돌은 일부 저장 후에도 생길 수 있으므로 실제 저장 결과에 따른 6.6과 7.3 안내를 유지한다. 기존 파일은 덮어쓰지 않는다.
- GZ 단일 파일의 출력 이름은 압축파일 이름에서 .gz를 뺀 값으로 제안하고 운영체제 기본 저장 창으로 선택한다. 취소하면 추출하지 않는다.
- 비어 있는 압축파일은 "이 압축파일은 비어 있습니다", 검색 결과가 없으면 "일치하는 항목이 없습니다"를 표시한다.

### 6.3 암호 입력

모달 창, 너비 420, 화면 가운데. 현재 지원하는 암호 ZIP은 목록을 읽을 때 암호를 묻지 않는다. 사용자가 [압축해제]를 눌러 추출을 시작한 뒤 작업자가 암호를 요청할 때 이 창을 연다. 암호 ZIP을 여는 것만으로는 띄우지 않는다.

```
+------------------------------------------+
| 암호가 필요합니다                        |
| sample.zip은 암호로 보호되어 있습니다.   |
|                                          |
| 암호  [**********************]  [보기]   |
|                                          |
|                     [취소]  [ 확인 ]     |
+------------------------------------------+
```

- 창이 열리면 암호 입력칸에 초점이 있다. 암호 입력칸에서 Enter를 누르면 화면의 입력 조건을 충족한 암호를 제출한다. 버튼에 초점이 있으면 Enter는 그 버튼만 실행한다([취소]에서는 제출하지 않는다). Esc는 취소다.
- 암호를 틀린 뒤 다시 열린 창에는 입력칸 아래에 오류색으로 "암호가 맞지 않습니다. 다시 입력하세요"를 보여 준다. 입력칸은 비우고 초점을 둔다.
- [보기]는 입력 내용을 보이거나 숨기는 토글이다. 기본은 숨김이다.
- [확인]이 주 버튼이다. 입력이 비어 있으면 비활성이다.

### 6.4 진행 중

화면 6.2의 목록 아래, 상태 줄 위에 진행 영역을 표시한다. 목록은 그대로 보이고 선택 변경은 막는다.

```
| 압축을 푸는 중                                               |
| [=========================------------------]  62%           |
| 12개 처리함, 38 MB / 61 MB                       [ 취소 ]    |
```

- 제목은 단계 문구를 쓴다(7장). 진행 막대는 전체 크기를 알 수 있으면 비율로, 알 수 없으면 움직이는 막대로 보여 준다. 알 수 없는 상태에서 퍼센트를 지어내지 않는다.
- [취소]는 위험 버튼 모양이다. 누르면 문구가 "취소하는 중..."으로 바뀌고 버튼은 비활성이 된다.
- 창을 닫으려 하면 기존의 "작업 중 닫기" 확인 창을 쓴다. 문구는 7장을 따른다.

### 6.5 완료

진행 영역이 결과 알림 상자로 바뀌며 하단 상태 줄은 유지한다.

```
| (성공 아이콘) 압축을 풀었습니다                              |
| D:\받은파일\sample 폴더에 저장했습니다.                      |
|                                  [폴더 열기]  [ 확인 ]       |
```

- 성공 알림 상자는 연한 녹색 배경에 녹색 아이콘이다. [폴더 열기]가 주 버튼이고 [확인]은 보조 버튼이다. [확인]을 누르면 6.2로 돌아간다.
- [폴더 열기]는 운영체제 파일 탐색기를 연다(Windows는 explorer, Ubuntu는 xdg-open, 경로는 셸을 거치지 않고 인자로 전달한다).
- 완료 판정과 저장 확인(내구성) 안내는 별도로 다룬다. Outcome::Completed에 Durability::Unconfirmed가 함께 와도 완료 안내와 [폴더 열기]를 유지하며, 저장 미확인 안내는 "자세히 보기" 안에만 둔다. 실패나 일부 추출의 경고 표시는 7.3을 따른다. 정상 결과에는 내부 상태 줄을 붙이지 않는다.
- ZIP 만들기 완료도 같은 모양이다. 제목은 "ZIP 파일을 만들었습니다", 본문은 저장한 파일의 전체 경로다.
- 취소로 끝났을 때는 회색 알림 상자에 "작업을 취소했습니다"를 보여 준다. 일부 파일이 남았다면 7.3 경고를 함께 보여 준다.

### 6.6 오류

완료와 같은 자리에 오류 알림 상자를 둔다. 연한 빨간 배경, 오류 아이콘.

```
| (오류 아이콘) 압축을 풀지 못했습니다                         |
| 디스크 여유 공간이 부족합니다. 공간을 확보한 뒤 다시         |
| 시도하세요.                                                  |
| [자세히 보기]                      [다시 시도]  [ 확인 ]     |
```

- 제목은 하는 일에 따라 "압축을 풀지 못했습니다", "압축파일을 열지 못했습니다", "ZIP 파일을 만들지 못했습니다"를 쓴다. 본문은 7.1의 오류 문구다.
- [다시 시도]가 주 버튼이다. 같은 요청을 다시 보낸다. 오류가 "원본 파일이 바뀌었습니다" 종류이면 [다시 시도] 대신 [압축파일 다시 열기]를 보여 준다.
- [자세히 보기]를 누르면 7.2의 내부 상태 줄을 연한 회색 상자에 펼친다. 기본은 접혀 있다.
- 같은 이름의 파일이 이미 있어 중단된 경우(충돌)에는 [다시 시도] 대신 [다른 폴더에 풀기]가 주 버튼이다. 본문은 "같은 이름의 파일이 이미 있습니다. 다른 폴더를 선택하세요"이며, 저장 결과는 7.3의 기준에 따라 별도로 안내한다. 누르면 6.8의 폴더 선택창이 열리고, 사용자가 폴더를 고르면 같은 선택 항목으로 다시 요청한다. 저장 여부가 불확실하면 먼저 기존 풀 위치를 확인하도록 경고하고, 확인과 사용자 선택 없이 자동으로 재요청하지 않는다. 이미 저장된 파일과 기존 파일은 지우거나 덮어쓰지 않는다. [확인]은 보조 버튼으로 6.2로 돌아간다.

### 6.7 ZIP 만들기 모달

첫 화면과 압축파일을 연 화면에서 모두 열 수 있다. [압축하기]는 일반 ZIP 만들기를 열고, [암호화]는 "암호로 보호하기"를 켠 상태로 같은 모달을 연다. 이는 총관리자가 정한 시안 해석이며 기존 압축파일에 암호를 다시 거는 기능은 아니다.

```
+----------------------------------------------------------+
| ZIP 만들기                                          [X]  |
|                                                          |
|  +- - - - - - - - - - - - - - - - - - - - - - - - - -+  |
|  |                    (파일 추가 아이콘)              |  |
|  |     파일이나 폴더를 여기에 끌어 놓으세요           |  |
|  +- - - - - - - - - - - - - - - - - - - - - - - - - -+  |
|  [폴더 추가]                                            |
|  추가한 파일과 폴더 목록 및 [빼기]                       |
|                                                          |
|  (잠금) 암호화                                          |
|  [ ] 암호로 보호하기                                    |
|                                  [취소] [압축하기]      |
+----------------------------------------------------------+
```

- 가운데 모달과 어두워진 배경, 제목, 우측 닫기 버튼, 넓은 점선 끌어 놓기 영역을 시안처럼 배치한다. 최소 창 크기에서는 모달 내용을 스크롤할 수 있게 해 버튼이 잘리지 않도록 한다.
- 끌어 놓기 영역을 클릭하면 운영체제 파일 선택창으로 파일을 추가한다. [폴더 추가]는 운영체제 폴더 선택창을 연다. 추가된 항목은 확인하고 뺄 수 있다.
- 끌어 놓기와 선택창 입력에 동일한 경로 검증을 적용한다. 접근할 수 없는 경로, 지원하지 않는 파일 종류와 안전하지 않은 경로는 설명과 함께 거부하며 기존 작업자의 경로 안전성 검증도 유지한다.
- 대상이 없으면 [압축하기]는 비활성이고 "묶을 파일이나 폴더를 추가하세요"를 툴팁으로 보여 준다.
- [압축하기]를 누르면 운영체제 저장 창에서 위치와 파일 이름을 고른다. 첫 항목 이름에 .zip을 붙인 이름과 첫 항목의 부모 폴더를 제안한다. 기존 파일을 덮어쓰지 않는 정책은 유지한다.
- 보호 옵션이 켜져 있으면 생성 요청 전에 "ZIP 암호 설정" 창에서 암호와 암호 확인을 받는다. 두 값이 같지 않으면 [확인]은 비활성이고 "두 암호가 같지 않습니다"를 표시한다. "암호를 잊으면 파일을 열 수 없습니다."를 함께 보여 준다.
- 저장 위치와 필요한 암호가 모두 확정되기 전에는 생성 요청을 보내지 않는다. 모달 [취소], [X], Esc 또는 저장 창 취소로 생성이 시작되지 않는다.
- 압축 방식의 기존 선택(Deflate 기본, Store)은 접힌 자세한 설정으로 유지한다. 폴더 추가는 기존 재귀 수집 기능을 사용한다.
- 생성이 시작되면 모달을 닫고 6.4 진행 영역을 보여 준다. 빈 화면에서 시작한 경우에도 같은 진행과 결과 규칙을 적용한다.

### 6.8 운영체제 기본 파일과 폴더 대화창

앱 안 파일 선택기는 제거한다. rfd는 `default-features = false`로 사용하고 Windows는 기본 백엔드, Linux는 GTK 없이 `xdg-portal`을 사용한다. rfd 및 전이 의존성의 라이선스 고지는 `packaging/licenses.py`로 갱신한다.

- [열기]: 압축파일을 고르는 운영체제 기본 파일 열기 창.
- ZIP 모달의 파일 추가: 운영체제 기본 파일 선택 창. 폴더 추가: 운영체제 기본 폴더 선택 창.
- ZIP 저장: .zip 기본 이름을 제안하는 운영체제 기본 저장 창.
- 압축해제 위치: 압축파일의 부모 폴더를 기본 위치로 여는 운영체제 기본 폴더 선택 창. 단일 파일의 저장 경로 선택도 운영체제 기본 저장 창을 사용한다.
- 대화창 취소는 결과 없음으로 처리한다. 열기 취소는 현재 압축파일을 유지하고, 추가 취소는 기존 추가 목록을 유지하며, 출력 위치 취소는 작업을 시작하지 않는다. 이전 대화창 결과를 재사용해 실행하지 않는다.
- 대화창 오류나 Linux portal 사용 불가는 쉬운 오류 안내로 표시하며 앱 안 선택기로 조용히 대체하지 않는다. 실패한 선택만으로 작업 요청이나 파일 생성을 하지 않는다.
- 운영체제 대화창 내부의 키보드 동작은 운영체제 표준을 따른다. 닫힌 뒤 입력을 앱에 중복 전달해 생성이나 추출을 시작하지 않는다.

오류 문구(현재 문구를 유지하는 것과 바꾸는 것):

### 7.2 숨길 내부 상태

- 동기화 상태: "동기화 해당 없음", "디스크 동기화 완료"
- 임시 파일 정리 상태: "작업 임시 파일 정리됨", "작업 임시 파일 정리 완료"
- 개수 줄: "생성 N개 / 남은 임시 파일 N개"
- 작업 ID, 요청 순서, 응답 순서 같은 내부 값

### 7.3 결과 상태별 저장 안내와 경고

저장 결과는 오류 코드와 별도로 판단한다. Conflict와 UnsafePath도 같은 기준을 따른다. 정상적으로 수집한 최종 결과에서 Publication::None, created_count=0, retained_partial_count=0, Cleanup::Complete가 확인되고, 출력 보고와 종료 확인에 누락이나 모순이 없을 때만 "아무 파일도 풀지 않았습니다" 또는 "파일은 저장하지 않았습니다"를 보여 준다. 생성 수가 0이라는 사실이나 오류 코드만으로는 이 문구를 쓰지 않는다. 최종 결과가 없거나 신뢰할 수 없으면 저장 여부 불확실 안내를 쓴다.

결과가 아래에 해당하면 완료 또는 오류 알림 상자 안에 경고(주황) 줄을 함께 보여 준다. 단, Outcome::Completed인 결과의 Durability::Unconfirmed 안내는 "자세히 보기" 안에만 표시하고 완료 안내와 [폴더 열기]를 유지한다. 이 저장 미확인 상태만으로 실패나 재시도로 바꾸지 않는다. 결과가 실패하거나 일부만 풀린 경우에는 저장 미확인 경고를 알림 상자에 바로 표시한다. 이 예외는 Durability::Unconfirmed에만 적용하며, CommitUncertain 또는 Publication::Uncertain의 저장 여부 불확실, 동기화 실패와 임시 파일 정리 경고를 숨기는 근거로 쓰지 않는다. 바로 표시해야 하는 경고를 미저장 안내로 대체하지 않는다.

- 실제 일부 추출: 요청에서 확정한 대상 파일 중 일부의 Created 보고만 확인되고 나머지가 저장되지 않은 것이 확인되면 "일부 파일만 풀렸습니다. 풀린 파일은 풀 위치 폴더에 남아 있습니다."를 보여 준다. PartialRetained는 임시 파일 잔존 보고이므로 이 판정의 근거로 쓰지 않는다. Publication::Partial이나 created_count만으로도 판정하지 않는다(생성 수에는 폴더가 포함될 수 있다).
- 전체 파일 저장 후 임시 파일 잔존: 대상 파일이 하나 이상이고 대상 파일 전체의 Created 보고가 확인되고 저장 여부에 불확실성이 없는데 PartialRetained 또는 retained_partial_count로 임시 파일 잔존이 확인되면 "선택한 파일은 모두 저장했지만 임시 파일을 지우지 못했습니다. 풀 위치 폴더를 확인하세요."를 보여 준다. 마지막 파일 저장 후 정리에 실패하면 Outcome::Failed와 Publication::Partial일 수 있으므로 Completed나 Complete만을 조건으로 삼지 않는다. 작업 전체를 정상 완료로 표시하지 않고, 동기화 경고가 있으면 함께 보여 준다.
- 저장 여부 불확실(CommitUncertain, 게시 불확실): "저장이 끝났는지 확인하지 못했습니다. 풀 위치 폴더를 확인하세요."
- 디스크 동기화 실패 또는 미확인: "파일을 디스크에 완전히 저장했는지 확인하지 못했습니다." Durability::Unconfirmed는 완료 결과에서는 "자세히 보기" 안의 보조 안내로, 실패 또는 일부 추출 결과에서는 알림 상자의 경고로 표시한다. Durability::Failed는 결과와 관계없이 경고를 바로 표시한다.
- 임시 파일 정리 실패 또는 미확인: "임시 파일을 지우지 못했습니다. 풀 위치 폴더에 남은 임시 파일이 있을 수 있습니다." 전체 파일 저장 후 임시 파일 잔존 안내를 이미 보여 줬으면 같은 경고를 반복하지 않는다. 일부 추출과 임시 파일 잔존이 함께 확인되면 두 사실을 모두 안내한다.

대상 파일과 Created 보고를 대조할 수 없거나 최종 결과와 모순되면 일부 또는 전체 추출을 단정하지 않고 저장 여부 불확실 안내를 우선한다. PartialRetained만 받은 경우에도 추출 완료 여부를 추정하지 않는다. 기존 결과와 임시 파일은 이 안내를 근거로 자동 삭제하지 않는다.

## 8. 접근성과 키보드

- eframe의 accesskit 기능은 이미 켜져 있다. 체크박스, 버튼, 입력칸에 한국어 이름이 읽히도록 레이블을 단다. 아이콘만 있는 요소에는 hover 텍스트와 접근성 이름을 단다.
- 모든 기능을 키보드로 쓸 수 있다. 다음 Enter 규칙은 앱 내부에 적용하며 운영체제 대화창은 6.8을 따른다. Tab 순서는 화면 위에서 아래, 왼쪽에서 오른쪽이다. Enter는 초점이 있는 활성 버튼만 실행하며, 화면의 주 버튼을 대신 실행하지 않는다. 버튼에 초점이 없거나 버튼이 비활성이면 Enter로 버튼 동작을 실행하지 않는다. Esc는 창 닫기 또는 취소다.
- 유일한 제출 예외는 암호 입력란이다. 암호 입력란에 초점이 있을 때 Enter로 화면의 입력 조건을 충족한 암호를 제출할 수 있다. ZIP 암호 설정은 암호 확인까지 일치해야 한다. 다른 입력란에는 이 예외를 적용하지 않는다. [취소] 등 보조 버튼에 초점이 있으면 해당 버튼만 실행하고 암호 제출, ZIP 생성이나 추출을 함께 시작하지 않는다. 같은 Enter 입력으로 두 동작을 실행하지 않는다.
- 색만으로 상태를 전하지 않는다. 성공, 경고, 오류는 아이콘과 제목 문구를 함께 쓴다.
- 창 크기를 줄여도(최소 760x540) 글자가 잘리거나 버튼이 겹치지 않는다. 긴 파일 이름은 가운데를 줄임표로 줄이고 전체 이름은 hover로 보여 준다.

## 9. 구현 메모

- 화면 구성 코드는 archive_screen.rs와 archive_ui.rs의 표시용 함수에 모은다. 문구 변환(오류 코드에서 문구, 단계에서 문구, 경고 판정)은 화면을 그리지 않는 순수 함수로 만들어 tests/에서 단위 시험한다.
- 색과 간격은 한 곳(상수 모듈)에 둔다. 화면 코드에 색 값을 직접 쓰지 않는다.
- 작업자 계약 revision 2의 필드와 태그는 바꾸지 않는다. 폴더 탐색과 선택 확장은 앱에서 처리하며 기존 실제 항목 ID로 요청한다. 완료 판정은 송신한 ID 집합을 사용한다.

## 10. 수용 기준

각 항목은 Xvfb 스크린샷 또는 tests/ 아래 시험으로 확인한다. 운영체제 기본 대화창은 Windows와 Linux portal 환경에서 별도 실행 확인하며 스크린샷만으로 동작 통과를 선언하지 않는다.

1. 빈 화면에도 네 툴바 버튼과 상태 줄이 보인다. 압축파일이 없을 때 압축해제는 비활성이며, 열기와 두 생성 진입점은 사용할 수 있다.
2. 파일을 창 위로 끌면 영역이 강조색으로 바뀌고 "놓으면 엽니다"가 보인다.
3. 창 제목에 압축파일 전체 경로와 Zipelo가 표시된다. 목록은 체크박스, 이름, 크기, 암호 열로 현재 폴더의 바로 아래 항목만 표시하며 폴더 아이콘은 주황색이다.
4. 툴바에 큰 아이콘과 글자의 [열기] [압축하기] [압축해제] [암호화]가 순서대로 보인다. 경로 줄과 검색, 하단 항목 수와 선택 수가 시안과 같은 위치에 있다.
5. 압축해제는 압축파일 옆을 기본 위치로 하는 운영체제 폴더 선택창을 열고, 확정 후에만 요청한다. GZ 단일 파일 저장 경로도 운영체제 저장 창에서 고른다.
6. 열기, 파일 추가, 폴더 추가, ZIP 저장 및 추출 위치 선택이 모두 운영체제 기본 대화창을 사용한다. 취소와 대화창 오류에서 요청과 파일 생성이 없고 기존 상태를 유지한다. 앱 안 선택기로 대체하지 않는다.
7. 폴더 체크 시 모든 하위 실제 ID를 포함하고 중복을 제거한다. 명시적 빈 폴더와 가상 폴더, 부모와 자식 중복 선택을 시험한다. 완료 판정의 대상 집합이 실제 요청과 일치한다. 선택이 없으면 전체 추출하며 검색 결과만으로 범위를 줄이지 않는다.
8. 정상 완료 화면에 "게시된 파일", "동기화", "임시 파일 N개" 같은 내부 문구가 없다. "자세히 보기"를 눌러야 보인다.
9. 7.3의 결과 상태별 표시 규칙을 따른다. tests/의 화면 시험에서 "완료 + 저장 미확인"은 완료 안내와 [폴더 열기]를 유지하고 저장 미확인 문구가 기본 화면에는 없으며 "자세히 보기"를 펼치면 보이는지 확인한다. "실패 + 저장 미확인"과 "일부만 풀림 + 저장 미확인"은 자세히 보기를 펼치지 않아도 해당 경고가 보이는지 각각 확인한다. 세 조합의 저장 미확인은 Durability::Unconfirmed이며, CommitUncertain 또는 Publication::Uncertain과 혼동하지 않는다. tests/의 문구 판정 시험은 최소한 다음 입력을 구분한다: 대상 파일 2개 중 Created 1개와 미저장 1개 확인 시 일부 추출 안내, 대상 파일 1개의 Created와 PartialRetained가 함께 있고 Outcome::Failed, Publication::Partial, created_count=1, retained_partial_count=1, Durability::Synced, Cleanup::Failed인 경우 전체 파일 저장 후 임시 파일 잔존 안내. 후자를 "일부 파일만 풀렸습니다"나 정상 완료로 표시하지 않는다. PartialRetained만 있고 대상 파일 저장 결과를 확인할 수 없는 경우와 CommitUncertain이 함께 있는 경우에는 저장 여부 불확실 안내를 확인한다. 동기화와 정리 경고의 동시 표시도 검증한다.
10. 모든 오류 코드가 7.1의 문구로 바뀌어 보인다. 내부 오류 묶음은 "내부 오류가 발생했습니다. 프로그램을 다시 시작해 주세요"로 보인다. UnsafePath는 오류 코드만으로 미저장을 단정하지 않고, 미저장 확인, 일부 저장, 저장 여부 불확실 결과를 각각 7.3에 따라 안내한다(시험: 오류 코드 전체에 대한 문구 매핑과 UnsafePath의 저장 결과별 판정).
11. 현재 지원하는 암호 ZIP을 열면 암호창 없이 목록이 표시된다. [압축해제]로 추출을 시작한 뒤 작업자의 암호 요청이 오면 6.3의 창이 뜨고 입력칸에 초점이 있다. 암호 입력칸 또는 [확인] 버튼에 초점이 있을 때 Enter로 확인하고, [취소] 버튼에서 Enter로 취소한다. Esc는 초점과 무관하게 취소한다. 틀린 암호 뒤 재입력 요청이 오면 입력칸을 비우고 오류 문구와 함께 다시 띄운다. 시험은 기존 tests/rust-app-real-worker/password_flows.rs의 encrypted_zip_list_and_extract_with_actual_password_dialog와 wrong_password_retry_clears_input_and_succeeds_without_partial_output 흐름을 재사용하며, 목록 열기 시 암호 요청 없음, 추출 시작 후 요청, 오입력 후 재요청 시점을 각각 확인한다. 3회 오입력 후 종료는 재입력 창으로 바꾸지 않고 기존 실패 흐름을 유지한다.
12. 암호 ZIP 만들기의 암호 창에는 입력칸이 둘이고, 두 값이 다르면 [확인]이 비활성이며 "두 암호가 같지 않습니다"가 보인다.
13. 진행 중 화면에 단계 문구, 진행 막대, [취소]가 보인다. 전체 크기를 모르면 퍼센트 없이 움직이는 막대다. [취소]를 누르면 "취소하는 중..."이 보이고 버튼이 비활성이 된다.
14. 완료 화면에서 [폴더 열기]가 풀 위치 폴더를 연다(경로를 셸 문자열로 이어 붙이지 않는다).
15. ZIP 만들기는 시안의 모달로 열리고 끌어 놓기 영역 클릭과 폴더 추가는 각각 기본 대화창을 연다. 대상이 없으면 압축하기가 비활성이다. 암호화 버튼으로 열면 보호 옵션이 켜진다. 저장 창에는 .zip 이름이 제안되며 저장이나 암호 입력 취소 시 생성하지 않는다.
16. 최소 창 크기 760x540에서 모든 화면이 잘리거나 겹치지 않는다.
17. 모든 버튼과 입력칸에 키보드 초점 윤곽선이 보이고 Tab으로 모든 기능에 닿는다. tests/의 공통 키보드 시험에서 모든 보조 버튼에 차례로 초점을 두고 Enter를 눌러 해당 버튼만 실행되고 ZIP 생성이나 추출 요청이 나가지 않는지 확인한다([열기], [위로], [폴더 추가], [취소] 포함). 주 버튼도 초점이 있을 때만 실행되며, 버튼 초점 없음과 비활성 버튼에서는 요청을 보내지 않는다. 암호 입력란에서 화면의 입력 조건을 충족한 제출만 예외로 허용하고, 입력 조건을 충족하지 않는 암호와 다른 입력란에서는 Enter로 제출하지 않는다. 암호창의 [취소]에 초점이 있으면 제출 없이 취소만 되며, 한 Enter 입력이 두 동작을 시작하지 않는다.
18. 색과 간격 값이 상수 모듈 한 곳에만 있다.
19. 작업자 계약 revision 2의 필드와 태그에 변경이 없다(계약 시험 통과).
20. 앱이 새 출력 폴더를 만드는 경로는 umask 0002에서도 Unix 권한 0700을 사용한다. 생성 실패 시 요청 없이 안내하고 다시 위치를 고를 수 있다. 기존 폴더 권한은 변경하지 않는다.
21. 앱이 이번 작업에서 만든 빈 폴더만, 작업이 실패하거나 취소된 뒤 지운다. 비어 있지 않은 폴더와 사용자가 고른 폴더는 지우지 않는다(시험: 두 경우).
22. 같은 이름의 파일이 있어 충돌로 끝나면 [다시 시도] 대신 [다른 폴더에 풀기]가 주 버튼으로 보이고, 사용자가 폴더를 고르면 같은 선택 항목으로 다시 요청한다. 문구는 7.1의 충돌 문구다. 미저장이 확인된 경우에만 "아무 파일도 풀지 않았습니다"를 덧붙이고, 일부 저장 또는 저장 여부 불확실이면 해당 경고를 보여 준다. 최종 결과 누락이나 모순을 미저장으로 표시하지 않으며, 기존 결과를 삭제하거나 사용자 확인 없이 재요청하지 않는다(시험: 충돌의 저장 결과별 판정과 재요청 동작).
23. 루트 목록, 하위 폴더 목록, ZIP 만들기 모달 세 화면의 시안 대비 Xvfb 스크린샷을 PR에 첨부한다. 기존 암호, 진행, 완료, 오류 화면도 회귀 확인한다. python3 tests/ci/run_rust.py local과 Windows 교차 빌드를 통과하고 THIRD-PARTY 고지 갱신을 확인한다.
24. 경로가 /에서 /Install로 이동하고 [위로]로 돌아온다. 명시적 폴더 항목이 없는 압축파일도 탐색할 수 있다. 검색은 현재 폴더 이름만 거르고, 검색 해제 뒤 목록을 복원한다.
25. 끌어 놓은 경로와 기본 대화창으로 고른 경로에 같은 안전성 검증을 적용하며, 유효하지 않은 경로로 작업 요청을 보내지 않는다. 모달이 열린 동안 배경의 열기와 압축해제가 실행되지 않는다.
26. 기존 렌더러 폴백, Enter 초점 규칙, 7.3의 결과와 저장 경고 조합을 유지한다. 운영체제 대화창에서 돌아온 Enter가 앱의 작업을 중복 실행하지 않는다.

## 11. 결정 상태

1. 기본 대화창(결정됨): 이준영 님의 2026-11-12 요청에 따라 파일과 폴더 및 저장 위치는 운영체제 기본 대화창을 쓴다. 총관리자는 rfd를 예외 라이브러리로 정하고 Linux는 xdg-portal, Windows는 기본 백엔드를 사용하도록 지정했다.
2. 폴더 선택(결정됨): 압축파일 내부 폴더 선택은 하위 실제 항목 전체로 확장하고, 요청과 완료 판정에 같은 ID 집합을 사용한다. 가상 폴더를 위한 계약 변경은 하지 않는다.
3. 암호화 버튼(총관리자 해석): 보호 옵션이 켜진 ZIP 만들기 모달을 연다. 기존 압축파일의 재암호화는 포함하지 않는다.
4. 폴더 생성과 결과 안전성(유지): 앱의 새 출력 폴더 0700 생성, 기존 파일 덮어쓰기 금지, 7.3 경고와 확정된 요청 범위의 완료 판정은 유지한다.
