# Zipelo v0.1 화면 설계

이 문서는 v0.1 앱 화면의 배치, 문구, 색과 간격, 구현 수용 기준을 정한다. 구현은 frontend 담당이 하고, 이 문서는 구현 요청의 기준이다. 기준 화면은 main(8bfa254)을 Xvfb로 찍은 빈 화면과 ZIP을 연 화면이다.

## 1. 전제와 제약

- 처음 쓰는 사람이 설명 없이 "열기 후 풀기"와 "ZIP 만들기"를 끝낼 수 있어야 한다.
- 새 외부 라이브러리를 추가하지 않는다. eframe 0.37 기본 위젯과 Painter로 직접 그린 아이콘만 쓴다.
- 작업자 계약 revision 2는 바꾸지 않는다. 화면은 계약에 이미 있는 값만 보여 준다.
- 화면 시험은 tests/ 아래에만 둔다.
- 이 문서의 디자인은 v0.1 범위다. 다크 모드, 미리보기, 설정 화면은 범위 밖이다.

## 2. 현재 화면의 문제

main(8bfa254) 스크린샷 두 장에서 확인한 사실이다.

- 회색 바탕에 작은 버튼 3개와 표 머리글만 있다. 끌어 놓을 영역이 보이지 않는데 "압축파일을 여기로 끌어 놓으세요"라는 문구만 있다.
- 열린 화면에서 출력 폴더는 빈 입력칸이고 폴더를 고르는 방법이 없다. 풀기 버튼이 다른 버튼과 같은 모양이다.
- 목록은 화면 왼쪽 절반에만 있고 아이콘이 없다.
- 하단에 "게시된 파일 없음", "생성 0개 / 남은 임시 파일 0개", "동기화 해당 없음 / 작업 임시 파일 정리 완료" 같은 내부 상태가 그대로 보인다.
- 파일 열기와 ZIP 만들기 창은 절대 경로를 직접 입력하게 한다. 일반 사용자는 경로를 외워서 입력하지 않는다.

## 3. 디자인 원칙

1. 한 화면에는 눈에 띄는 버튼이 하나만 있다. 지금 해야 할 다음 행동이다.
2. 사용자가 고르는 것은 경로 문자열이 아니라 파일과 폴더다.
3. 정상일 때는 내부 상태를 숨긴다. 결과가 정상이 아닐 때(일부만 풀림, 저장 여부 불확실 등)는 숨기지 않고 쉬운 문장으로 알린다.
4. 오류 문구는 무엇이 잘못됐는지와 사용자가 할 수 있는 일을 함께 말한다.
5. 영어 약어와 내부 용어(작업자, 프로세스, 게시, 동기화)를 화면에 쓰지 않는다.

## 4. 디자인 토큰

라이트 테마 하나만 만든다. 글자 대비는 흰 배경 기준 4.5 대 1 이상이다.

색:

- 창 배경 #F7F8FA, 패널과 목록 배경 #FFFFFF, 줄무늬 행 #F3F5F8, 테두리 #D9DEE5
- 본문 글자 #1F2933, 보조 글자 #5B6673
- 주 버튼 배경 #2563EB(글자 흰색), 마우스를 올리면 #1D4ED8, 누르면 #1E40AF
- 선택한 행 #E8F0FE, 끌어 놓기 강조 배경 #EEF4FF
- 성공 #15803D, 경고 #B45309, 오류 #B91C1C. 알림 상자 배경은 각 색의 10퍼센트 농도로 쓴다.
- 아이콘 색: 폴더 #E0A526, 파일 #7B8794, 압축파일 #2563EB, 잠금 #B45309

글꼴(시스템 CJK 글꼴 그대로): 제목 22, 큰 안내 문구 20, 본문 15, 보조 13. 13보다 작은 글자는 쓰지 않는다.

간격은 8의 배수(8, 16, 24, 32)만 쓴다. 창 안쪽 여백 16, 패널 안쪽 여백 16, 행 높이 32, 모서리 둥글기는 버튼 6과 패널 8, 끌어 놓기 영역 12.

버튼:

- 주 버튼: 높이 40, 최소 너비 112, 파란 배경에 흰 글자, 굵게. 화면당 하나.
- 보조 버튼: 높이 36, 흰 배경, 테두리 #D9DEE5, 본문 글자.
- 위험 또는 취소 버튼: 보조 버튼 모양에 글자색만 오류색.
- 비활성 버튼: 투명도 40퍼센트. 마우스를 올리면 이유를 툴팁으로 보여 준다(예: "먼저 압축파일을 여세요").
- 키보드 초점: 2px 파란 윤곽선(#2563EB)을 모든 버튼, 입력칸, 체크박스에 그린다.

창: 기본 1060x720, 최소 760x540(현재 값 유지). 목록과 영역은 창 너비를 모두 쓴다.

## 5. 아이콘

외부 이미지 파일 없이 Painter로 그린다. 16과 20 크기를 쓰고 선 두께는 1.5.

- 폴더: 둥근 사각형에 왼쪽 위 탭
- 파일: 오른쪽 위가 접힌 사각형
- 압축파일: 파일 모양에 가로 줄무늬 세 개
- 잠금: 둥근 사각형과 위쪽 반원
- 성공(원 안의 체크), 경고(삼각형 안의 느낌표), 오류(원 안의 가위표)
- 끌어 놓기 영역 대표 아이콘은 48 크기의 압축파일 아이콘 하나

## 6. 화면 상태별 배치

모든 화면 위쪽에는 같은 상단 막대가 있다. 왼쪽에 앱 이름 "Zipelo", 오른쪽에 [ZIP 만들기] 보조 버튼 하나만 둔다. 작업 중에는 [ZIP 만들기]가 비활성이다.

### 6.1 빈 화면

```
+--------------------------------------------------------------+
| Zipelo                                         [ZIP 만들기]  |
+--------------------------------------------------------------+
|                                                              |
|     +- - - - - - - - - - - - - - - - - - - - - - - -+        |
|     |                                                |        |
|     |                  (압축파일 아이콘)             |        |
|     |        압축파일을 여기에 끌어 놓으세요         |        |
|     |                      또는                      |        |
|     |                 [ 파일 열기 ]                  |        |
|     |                                                |        |
|     +- - - - - - - - - - - - - - - - - - - - - - - -+        |
|     ZIP, 7z, TAR, GZ, TAR.GZ 파일을 열 수 있습니다           |
+--------------------------------------------------------------+
```

- 끌어 놓기 영역은 창 가운데에 놓는다. 너비는 창의 60퍼센트(최소 480), 높이 280, 2px 점선 테두리 #AAB4C0, 흰 배경.
- 파일을 창 위로 끌고 오면(hovered_files) 영역이 #EEF4FF 배경과 #2563EB 실선 테두리로 바뀌고 문구가 "놓으면 엽니다"로 바뀐다. 창 어디에 놓아도 열린다.
- [파일 열기]가 주 버튼이다.
- 하단 상태 줄은 두지 않는다.

### 6.2 압축파일 열림

```
+--------------------------------------------------------------+
| Zipelo                                         [ZIP 만들기]  |
+--------------------------------------------------------------+
| (압축파일 아이콘) sample.zip                      [다른 파일]|
| 항목 3개, 21 B                                               |
+--------------------------------------------------------------+
| [ ] 이름                                   크기     암호     |
| [ ] (파일) doc1.txt                        7 B               |
| [ ] (파일) doc2.txt                        7 B               |
| [ ] (폴더) docs                                              |
|                                                              |
+--------------------------------------------------------------+
| 풀 위치  D:\받은파일\sample           [폴더 바꾸기]          |
| [ ] 선택한 항목만 풀기                          [ 풀기 ]     |
+--------------------------------------------------------------+
```

- 머리 영역: 아이콘과 압축파일 이름(제목 크기), 아래에 "항목 N개, 합계 크기". 오른쪽 끝에 [다른 파일] 보조 버튼(파일 열기 선택창을 연다).
- 목록은 창 너비 전체를 쓰고 남는 높이를 채우며 세로 스크롤한다. 열은 선택(체크박스), 이름(아이콘과 함께, 남는 너비를 모두 씀), 크기(오른쪽 정렬, 너비 96), 암호(잠금 아이콘, 너비 64). 머리글의 체크박스는 전체 선택이다.
- "형식" 열은 없앤다. 폴더는 이름 앞 아이콘으로 구분한다. 링크와 기타 종류는 파일 아이콘에 "(링크)"를 이름 뒤에 붙인다.
- 행을 클릭하면 선택이 바뀐다. 줄무늬와 선택 배경색을 쓴다.
- 수정 날짜 열은 v0.1에서 넣지 않는다. 현재 목록 항목에 날짜가 없고, 넣으려면 작업자 계약 변경이 필요해서 총관리자가 다음 버전으로 미루기로 정했다(11장 참고).
- 하단 작업 영역은 흰 패널에 위쪽 테두리를 둔다. "풀 위치"는 읽기 전용 경로 표시와 [폴더 바꾸기]로 구성한다. 기본 풀 위치는 압축파일이 있는 폴더 아래 "압축파일 이름(확장자 제외)" 폴더다.
- 풀 위치 폴더 만들기: 작업자는 풀 위치 폴더 자체를 만들지 않고 그 안의 하위 폴더만 만든다(시로사키 하나 님 확인). 그래서 [풀기]를 누르면 앱이 작업자에 요청을 보내기 전에 기본 풀 위치 폴더를 직접 만든다. 이미 있는 폴더는 그대로 쓴다. 폴더를 만들지 못하면 요청을 보내지 않고 "풀 위치 폴더를 만들 수 없습니다. 접근 권한을 확인하세요"를 보여 주며 [폴더 바꾸기]를 눌러 다른 곳을 고르게 한다. 작업이 실패하거나 취소되었을 때, 앱이 이번 작업에서 만들었고 비어 있는 폴더만 지운다(비어 있지 않으면 그대로 둔다). 사용자가 고른 폴더는 지우지 않는다.
- 같은 이름의 파일이 이미 있을 때: 작업자는 이 경우 해제 전체를 시작하기 전에 중단한다(파일 하나만 건너뛰지 않는다). 앱은 6.6의 충돌 안내를 보여 주고 다른 폴더에 풀도록 안내한다.
- [풀기]가 주 버튼이며 오른쪽 아래에 둔다. 선택 항목이 없고 "선택한 항목만 풀기"가 켜져 있으면 비활성이고 툴팁은 "풀 항목을 선택하세요"이다.
- GZ 파일(단일 파일 압축)은 "풀 위치" 아래에 "저장할 파일 이름" 입력칸을 한 줄 더 보여 준다. 기본값은 압축파일 이름에서 .gz를 뺀 값이다.
- 항목이 없으면 목록 가운데에 "이 압축파일은 비어 있습니다"를 보여 준다.

### 6.3 암호 입력

모달 창, 너비 420, 화면 가운데.

```
+------------------------------------------+
| 암호가 필요합니다                        |
| sample.zip은 암호로 보호되어 있습니다.   |
|                                          |
| 암호  [**********************]  [보기]   |
|                                          |
|                     [취소]  [ 확인 ]     |
+------------------------------------------+
```

- 창이 열리면 암호 입력칸에 초점이 있다. Enter가 확인, Esc가 취소다.
- 암호를 틀린 뒤 다시 열린 창에는 입력칸 아래에 오류색으로 "암호가 맞지 않습니다. 다시 입력하세요"를 보여 준다. 입력칸은 비우고 초점을 둔다.
- [보기]는 입력 내용을 보이거나 숨기는 토글이다. 기본은 숨김이다.
- [확인]이 주 버튼이다. 입력이 비어 있으면 비활성이다.

### 6.4 진행 중

화면 6.2의 하단 작업 영역이 진행 영역으로 바뀐다. 목록은 그대로 보이고 선택 변경은 막는다.

```
| 압축을 푸는 중                                               |
| [=========================------------------]  62%           |
| 12개 처리함, 38 MB / 61 MB                       [ 취소 ]    |
```

- 제목은 단계 문구를 쓴다(7장). 진행 막대는 전체 크기를 알 수 있으면 비율로, 알 수 없으면 움직이는 막대로 보여 준다. 알 수 없는 상태에서 퍼센트를 지어내지 않는다.
- [취소]는 위험 버튼 모양이다. 누르면 문구가 "취소하는 중..."으로 바뀌고 버튼은 비활성이 된다.
- 창을 닫으려 하면 기존의 "작업 중 닫기" 확인 창을 쓴다. 문구는 7장을 따른다.

### 6.5 완료

하단 작업 영역이 결과 알림 상자로 바뀐다.

```
| (성공 아이콘) 압축을 풀었습니다                              |
| D:\받은파일\sample 폴더에 저장했습니다.                      |
|                                  [폴더 열기]  [ 확인 ]       |
```

- 성공 알림 상자는 연한 녹색 배경에 녹색 아이콘이다. [폴더 열기]가 주 버튼이고 [확인]은 보조 버튼이다. [확인]을 누르면 6.2로 돌아간다.
- [폴더 열기]는 운영체제 파일 탐색기를 연다(Windows는 explorer, Ubuntu는 xdg-open, 경로는 셸을 거치지 않고 인자로 전달한다).
- 정상이 아닌 결과는 7.3의 경고 문구로 대신 보여 준다. 정상 결과에는 내부 상태 줄을 붙이지 않는다.
- ZIP 만들기 완료도 같은 모양이다. 제목은 "ZIP 파일을 만들었습니다", 본문은 저장한 파일의 전체 경로다.
- 취소로 끝났을 때는 회색 알림 상자에 "작업을 취소했습니다"를 보여 준다. 일부 파일이 남았다면 7.3 경고를 함께 보여 준다.

### 6.6 오류

완료와 같은 자리에 오류 알림 상자를 둔다. 연한 빨간 배경, 오류 아이콘.

```
| (오류 아이콘) 압축을 풀지 못했습니다                         |
| 디스크 여유 공간이 부족합니다. 공간을 확보한 뒤 다시         |
| 시도하세요.                                                  |
| [자세히 보기]                      [다시 시도]  [ 확인 ]     |
```

- 제목은 하는 일에 따라 "압축을 풀지 못했습니다", "압축파일을 열지 못했습니다", "ZIP 파일을 만들지 못했습니다"를 쓴다. 본문은 7.1의 오류 문구다.
- [다시 시도]가 주 버튼이다. 같은 요청을 다시 보낸다. 오류가 "원본 파일이 바뀌었습니다" 종류이면 [다시 시도] 대신 [압축파일 다시 열기]를 보여 준다.
- [자세히 보기]를 누르면 7.2의 내부 상태 줄을 연한 회색 상자에 펼친다. 기본은 접혀 있다.
- 같은 이름의 파일이 이미 있어 중단된 경우(충돌)에는 [다시 시도]가 같은 결과를 내므로 쓰지 않는다. 본문은 "같은 이름의 파일이 이미 있습니다. 아무 파일도 풀지 않았습니다. 다른 폴더를 선택하세요"이고 주 버튼은 [다른 폴더에 풀기]다. 누르면 6.8의 폴더 선택창이 열리고, 폴더를 고르면 같은 선택 항목으로 바로 다시 요청한다. [확인]은 보조 버튼으로 6.2로 돌아간다.

### 6.7 ZIP 만들기

모달 창, 너비 560. 첫 화면에서도, 압축파일을 연 상태에서도 열 수 있다.

```
+----------------------------------------------------------+
| ZIP 만들기                                               |
|                                                          |
| 1. 묶을 파일과 폴더                                      |
|  +----------------------------------------------------+  |
|  | (폴더) 사진                                [빼기]  |  |
|  | (파일) 메모.txt                            [빼기]  |  |
|  | 여기에 파일이나 폴더를 끌어 놓을 수도 있습니다     |  |
|  +----------------------------------------------------+  |
|  [파일 추가]  [폴더 추가]                                |
|                                                          |
| 2. 저장 위치                                             |
|  이름 [사진.zip                      ]                   |
|  폴더 D:\받은파일                        [폴더 바꾸기]   |
|                                                          |
| 3. 보호                                                  |
|  [ ] 암호로 보호하기                                     |
|                                                          |
|  [자세한 설정 v]                      [취소] [ 만들기 ]  |
+----------------------------------------------------------+
```

- 번호 단계는 위에서 아래로 읽는다. 각 단계 제목은 15 굵게.
- 목록이 비어 있으면 [만들기]가 비활성이고 툴팁은 "묶을 파일이나 폴더를 추가하세요"이다.
- 이름 기본값은 첫 항목 이름에 .zip을 붙인 것이다. 폴더 기본값은 첫 항목이 있는 폴더다. 같은 이름의 파일이 이미 있으면 [만들기]를 누를 때 7.1의 "같은 이름의 파일이 있습니다" 문구를 이름 칸 아래에 보여 준다.
- "암호로 보호하기"를 켜고 [만들기]를 누르면 6.3과 같은 모양의 "ZIP 암호 설정" 창이 열린다. 이 창에는 입력칸이 둘이다. "암호"와 "암호 확인"이 같지 않으면 [확인]이 비활성이고 오류색으로 "두 암호가 같지 않습니다"를 보여 준다. 암호를 잊으면 복구할 수 없다는 문장을 보조 글자로 한 줄 보여 준다: "암호를 잊으면 파일을 열 수 없습니다."
- "자세한 설정"은 기본으로 접혀 있다. 안에는 압축 방식 두 가지가 있다: "작게 압축(기본)"(Deflate), "빠르게 묶기"(Store).
- "폴더 추가"는 작업자가 폴더를 재귀로 수집하는 수정(fix/zip-folder-input)이 병합되어야 동작한다. 그 전에는 폴더를 넘기면 파일 접근 오류가 난다(Windows 11 VM 시험). 구현은 이 수정이 main에 들어간 뒤 "폴더 추가"를 연결한다.
- 만들기를 시작하면 이 창은 닫히고 6.4의 진행 영역이 보인다. 첫 화면에서 시작했다면 진행 영역은 빈 화면 대신 6.4 모양의 전체 화면 카드로 보여 준다.

### 6.8 파일과 폴더 고르기 창

운영체제 파일 선택창을 쓰려면 새 라이브러리가 필요하므로(11장 결정 1) v0.1은 앱 안에서 직접 그리는 선택창을 쓴다. 파일 열기, 폴더 바꾸기, 파일 추가, 폴더 추가가 모두 이 창을 쓴다.

- 위쪽: 현재 경로를 폴더 단위 버튼으로 나눠 보여 준다(누르면 그 폴더로 이동). 왼쪽: 바로가기 목록(홈, 바탕 화면, 문서, 다운로드, Windows는 사용 가능한 드라이브). 가운데: 현재 폴더의 하위 폴더와 파일 목록.
- 파일 열기에서는 파일을 두 번 클릭하거나 선택 후 [열기]를 누른다. 폴더 선택에서는 [이 폴더 선택]이 주 버튼이다.
- 폴더 읽기에 실패하면 목록 자리에 "이 폴더를 열 수 없습니다. 접근 권한을 확인하세요"를 보여 준다.
- 구현은 표준 라이브러리(std::fs)만 쓴다. 심볼릭 링크는 따라가지 않고 링크 아이콘으로 표시하되 선택은 허용한다.

## 7. 문구

### 7.1 사용자에게 보여 줄 문구

단계 문구(진행 영역 제목):

- 목록 읽는 중: "압축파일을 읽는 중"
- 파일 읽는 중: "압축파일을 읽는 중"
- 압축 푸는 중: "압축을 푸는 중" (ZIP 만들기 작업이면 "압축하는 중")
- 파일 쓰는 중: "파일을 저장하는 중"
- 검증 중: "확인하는 중"
- 저장 마무리 중: "마무리하는 중"
- 암호 대기: "암호를 입력하세요"
- 취소 요청 접수, 취소 요청 전송: "취소하는 중..."
- 작업 결과 수신과 프로세스 종료 확인 중: "마무리하는 중"

오류 문구(현재 문구를 유지하는 것과 바꾸는 것):

- 유지: "압축파일이 손상됐습니다", "지원하지 않는 압축 형식입니다", "아직 지원하지 않는 기능입니다", "암호가 올바르지 않습니다", "처리 한도를 초과했습니다", "원본 파일이 바뀌었습니다. 압축파일을 다시 여세요", "디스크 여유 공간이 부족합니다. 공간을 확보한 뒤 다시 시도하세요", "파일을 읽거나 쓰지 못했습니다. 파일과 폴더의 접근 권한을 확인하세요"
- 바꿈: "안전하지 않은 경로가 있어 중단했습니다"는 "압축파일 안에 풀 위치 밖을 가리키는 경로가 있어 중단했습니다. 파일은 저장하지 않았습니다"로 바꾼다.
- 바꿈: "같은 이름의 파일이 있습니다. 다른 출력 폴더를 선택하세요"는 "같은 이름의 파일이 이미 있습니다. 아무 파일도 풀지 않았습니다. 다른 폴더를 선택하세요"로 바꾼다.
- 추가(앱이 직접 내는 문구): "풀 위치 폴더를 만들 수 없습니다. 접근 권한을 확인하세요"
- 바꿈(내부 오류 묶음): Protocol, Internal, 작업 ID와 응답 순서 불일치, 요청 순서 한도, 출력 보고 한도, 작업 승인 응답 없음 같은 문구는 모두 "내부 오류가 발생했습니다. 프로그램을 다시 시작해 주세요"로 보여 주고 원래 문구는 "자세히 보기"에만 둔다.
- 바꿈: "입력과 선택한 항목을 확인하세요"와 "입력 경로, 출력명과 선택한 목록을 확인하세요"는 "풀 위치와 선택한 항목을 확인하세요"로 합친다.
- 바꿈: "작업자 종료 결과를 확인할 수 없습니다. 출력 상태를 확인하세요"는 "작업이 정상적으로 끝났는지 확인하지 못했습니다. 풀 위치 폴더를 확인하세요"로 바꾼다.

고정 문구:

- 빈 화면: "압축파일을 여기에 끌어 놓으세요", "또는", "ZIP, 7z, TAR, GZ, TAR.GZ 파일을 열 수 있습니다", "놓으면 엽니다"
- 닫기 확인 창 "작업 중 닫기": "작업을 취소하고 닫을까요?", 버튼 [계속 작업]과 [취소하고 닫기]
- "종료 확인 중" 창: "마무리하는 중입니다. 잠시만 기다려 주세요", 버튼 [닫기 취소]

### 7.2 숨길 내부 상태

기본 화면에서 보이지 않게 하고 "자세히 보기"를 눌렀을 때만 펼친다.

- 게시 상태: "게시된 파일 없음", "일부 파일 게시됨", "파일 게시 완료"
- 동기화 상태: "동기화 해당 없음", "디스크 동기화 완료"
- 임시 파일 정리 상태: "작업 임시 파일 정리됨", "작업 임시 파일 정리 완료"
- 개수 줄: "생성 N개 / 남은 임시 파일 N개"
- 작업 ID, 요청 순서, 응답 순서 같은 내부 값
- 작업자 연결 상태 문구
- "화면 시험 모드 / 파일을 읽거나 저장하지 않습니다" 배너는 가짜 작업자 기능을 켠 시험 빌드에서만 보인다. 일반 빌드에는 나타나지 않는다.

### 7.3 정상이 아닐 때 반드시 보여 줄 경고

결과가 아래에 해당하면 완료 또는 오류 알림 상자 안에 경고(주황) 줄을 함께 보여 준다. 숨기지 않는다.

- 일부 파일만 남음(PartialRetained, 게시 일부): "일부 파일만 풀렸습니다. 풀린 파일은 풀 위치 폴더에 남아 있습니다."
- 저장 여부 불확실(CommitUncertain, 게시 불확실): "저장이 끝났는지 확인하지 못했습니다. 풀 위치 폴더를 확인하세요."
- 디스크 동기화 실패 또는 미확인: "파일을 디스크에 완전히 저장했는지 확인하지 못했습니다."
- 임시 파일 정리 실패 또는 미확인: "임시 파일을 지우지 못했습니다. 풀 위치 폴더에 남은 임시 파일이 있을 수 있습니다."

## 8. 접근성과 키보드

- eframe의 accesskit 기능은 이미 켜져 있다. 체크박스, 버튼, 입력칸에 한국어 이름이 읽히도록 레이블을 단다. 아이콘만 있는 요소에는 hover 텍스트와 접근성 이름을 단다.
- 모든 기능을 키보드로 쓸 수 있다. Tab 순서는 화면 위에서 아래, 왼쪽에서 오른쪽이다. Enter는 창의 주 버튼, Esc는 창 닫기 또는 취소다.
- 색만으로 상태를 전하지 않는다. 성공, 경고, 오류는 아이콘과 제목 문구를 함께 쓴다.
- 창 크기를 줄여도(최소 760x540) 글자가 잘리거나 버튼이 겹치지 않는다. 긴 파일 이름은 가운데를 줄임표로 줄이고 전체 이름은 hover로 보여 준다.

## 9. 구현 메모

- 화면 구성 코드는 archive_screen.rs와 archive_ui.rs의 표시용 함수에 모은다. 문구 변환(오류 코드에서 문구, 단계에서 문구, 경고 판정)은 화면을 그리지 않는 순수 함수로 만들어 tests/에서 단위 시험한다.
- 색과 간격은 한 곳(상수 모듈)에 둔다. 화면 코드에 색 값을 직접 쓰지 않는다.
- 작업자 계약 revision 2의 필드와 태그는 바꾸지 않는다. 화면은 기존 상태와 결과값을 읽어 문구만 바꾼다.

## 10. 수용 기준

각 항목은 Xvfb 스크린샷 또는 tests/ 아래 시험으로 확인한다.

1. 빈 화면에 끌어 놓기 영역(점선 테두리, 아이콘, 안내 문구)과 주 버튼 [파일 열기]가 보이고, 하단 상태 줄이 없다.
2. 파일을 창 위로 끌면 영역이 강조색으로 바뀌고 "놓으면 엽니다"가 보인다.
3. ZIP을 열면 압축파일 이름, "항목 N개, 합계 크기", 아이콘이 있는 목록이 창 너비 전체에 보이고 "형식" 열이 없다.
4. 열린 화면에서 [풀기]가 파란 주 버튼이고, 같은 화면에 파란 버튼이 하나뿐이다.
5. "풀 위치"에 기본 경로(압축파일 폴더 아래 압축파일 이름 폴더)가 미리 채워져 있고 사용자가 경로를 입력하지 않아도 [풀기]가 가능하다. 그 폴더가 없으면 앱이 요청 전에 만든다.
6. [폴더 바꾸기]와 [파일 열기]가 앱 안 선택창을 연다. 경로 직접 입력칸은 사용자 화면에 없다.
7. 선택 항목이 없고 "선택한 항목만 풀기"가 켜져 있으면 [풀기]가 비활성이고 이유 툴팁이 나온다.
8. 정상 완료 화면에 "게시된 파일", "동기화", "임시 파일 N개" 같은 내부 문구가 없다. "자세히 보기"를 눌러야 보인다.
9. 7.3의 네 가지 경우에는 각각 해당 경고 문구가 완료 또는 오류 상자에 보인다(시험: 경우별 문구 판정 함수의 단위 시험).
10. 모든 오류 코드가 7.1의 문구로 바뀌어 보인다. 내부 오류 묶음은 "내부 오류가 발생했습니다. 프로그램을 다시 시작해 주세요"로 보인다(시험: 오류 코드 전체에 대한 문구 매핑 시험).
11. 암호가 필요한 ZIP을 열면 6.3의 창이 뜨고 입력칸에 초점이 있다. Enter로 확인, Esc로 취소가 된다. 틀린 암호 뒤에 같은 창이 오류 문구와 함께 다시 뜬다.
12. 암호 ZIP 만들기의 암호 창에는 입력칸이 둘이고, 두 값이 다르면 [확인]이 비활성이며 "두 암호가 같지 않습니다"가 보인다.
13. 진행 중 화면에 단계 문구, 진행 막대, [취소]가 보인다. 전체 크기를 모르면 퍼센트 없이 움직이는 막대다. [취소]를 누르면 "취소하는 중..."이 보이고 버튼이 비활성이 된다.
14. 완료 화면에서 [폴더 열기]가 풀 위치 폴더를 연다(경로를 셸 문자열로 이어 붙이지 않는다).
15. ZIP 만들기 창에서 파일과 폴더를 추가하고 끌어 놓을 수 있고, 이름과 저장 폴더 기본값이 자동으로 채워지며, 목록이 비면 [만들기]가 비활성이다.
16. 최소 창 크기 760x540에서 모든 화면이 잘리거나 겹치지 않는다.
17. 모든 버튼과 입력칸에 키보드 초점 윤곽선이 보이고 Tab으로 모든 기능에 닿는다.
18. 색과 간격 값이 상수 모듈 한 곳에만 있다.
19. 작업자 계약 revision 2의 필드와 태그에 변경이 없다(계약 시험 통과).
20. 기본 풀 위치 폴더가 없을 때 [풀기]를 누르면 앱이 폴더를 만든 뒤 요청한다. 폴더를 만들 수 없으면 요청을 보내지 않고 "풀 위치 폴더를 만들 수 없습니다. 접근 권한을 확인하세요"와 [폴더 바꾸기]가 보인다(시험: 임시 폴더에서 생성 성공과 실패 경로).
21. 앱이 이번 작업에서 만든 빈 폴더만, 작업이 실패하거나 취소된 뒤 지운다. 비어 있지 않은 폴더와 사용자가 고른 폴더는 지우지 않는다(시험: 두 경우).
22. 같은 이름의 파일이 있어 충돌로 끝나면 [다시 시도] 대신 [다른 폴더에 풀기]가 주 버튼으로 보이고, 폴더를 고르면 같은 선택 항목으로 다시 요청한다. 문구는 7.1의 충돌 문구다.
23. 위 1부터 8, 11부터 13, 15의 상태별 화면을 Xvfb로 찍은 전후 스크린샷이 PR 본문에 있다. `python3 tests/ci/run_rust.py local`이 통과한다.

## 11. 결정 상태

1. 파일 선택창(열린 결정): 운영체제 기본 선택창은 새 외부 라이브러리(rfd, MIT 또는 Apache)가 필요하다. 총관리자는 rfd 허용을 추천했고 이준영 님의 답을 기다리고 있다. 답이 오기 전까지는 이 문서의 6.8 앱 안 선택창을 기준으로 구현한다. rfd가 허용되면 6.8은 운영체제 기본 선택창 호출로 바뀌고, 6.2와 6.7의 나머지 동작은 그대로다.
2. 풀 위치 폴더 생성(결정됨): 작업자는 그대로 두고 앱이 요청 전에 기본 풀 위치 폴더를 만든다. 같은 이름의 파일이 있으면 작업자가 해제 전체를 미리 중단하고, 앱은 충돌 안내와 다른 폴더 선택을 보여 준다. 계약은 바꾸지 않는다. 6.2, 6.6, 7.1과 수용 기준 20부터 22에 반영했다.
3. 수정 날짜 열(결정됨): v0.1에서 넣지 않는다. 계약 변경이 필요해서 다음 버전으로 넘긴다.
