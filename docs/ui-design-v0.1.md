# Zipelo v0.1 화면 설계

이 문서는 v0.1 앱 화면의 배치, 문구, 색과 간격, 구현 수용 기준을 정한다. 구현은 frontend 담당이 하고, 이 문서는 구현 요청의 기준이다. 기준은 이준영 님의 초기 시안과 이후 직접 올려 병합된 UI 변경이다. 진행/결과 창과 ZIP 만들기 흐름은 PR95와 PR100이 병합된 main 97357bd의 동작을 반영한다.

## 1. 전제와 제약

- 처음 쓰는 사람이 설명 없이 "열기 후 풀기"와 "ZIP 만들기"를 끝낼 수 있어야 한다.
- 앱 화면은 eframe 기본 위젯과 Painter 아이콘을 쓴다. 운영체제 기본 파일 창용 rfd를 외부 라이브러리 예외로 사용한다. 기존 렌더러 폴백과 작업자 계약은 유지한다.
- 작업자 계약 revision 2는 바꾸지 않는다. 화면은 계약에 이미 있는 값만 보여 준다.
- 화면 시험은 tests/ 아래에만 둔다.
- 이 문서의 디자인은 v0.1 범위다. 다크 모드, 미리보기, 설정 화면은 범위 밖이다.

## 2. 새 시안의 적용 범위

기존 전체 경로 나열 목록을 폴더 단위 탐색으로 바꾸고, 상단 툴바와 경로 줄, 검색, 하단 상태 줄을 추가한다. ZIP 만들기와 작업 진행/결과는 별도 창으로 구성한다. 별도 창을 만들 수 없는 환경의 대체 배치는 6.4와 6.7을 따른다. 파일과 폴더 및 저장 위치 선택은 운영체제 기본 대화창을 사용한다. 기존 완료 판정과 저장 경고 표시 규칙은 7.3을 유지한다.

## 3. 디자인 원칙

1. 주요 기능 세 개는 큰 아이콘과 글자가 있는 툴바에 모은다. 작업 창의 실행 버튼과 결과 화면의 다음 행동은 파란 주 버튼으로 구분한다.
2. 사용자가 고르는 것은 경로 문자열이 아니라 파일과 폴더다.
3. 정상일 때는 내부 상태를 숨긴다. 결과가 정상이 아닐 때(일부만 풀림, 저장 여부 불확실 등)는 숨기지 않고 쉬운 문장으로 알린다.
4. 오류 문구는 무엇이 잘못됐는지와 사용자가 할 수 있는 일을 함께 말한다.
5. 영어 약어와 내부 용어(작업자, 프로세스, 게시, 동기화)를 화면에 쓰지 않는다.
6. fade-in, fade-out, 색 전환과 진행 표시를 포함해 애니메이션을 쓰지 않는다. 상호작용과 실제 진행 값의 변경은 즉시 반영한다.

## 5. 아이콘

외부 이미지 파일 없이 Painter로 그린다. 목록에는 16과 20 크기, 툴바에는 40 크기를 쓰고 선 두께는 크기에 맞춰 조정한다.

- 폴더: 둥근 사각형에 왼쪽 위 탭, 주황색
- 툴바: 열기는 폴더 윤곽, 압축하기는 파일과 더하기, 압축해제는 아래 화살표
- 파일: 오른쪽 위가 접힌 사각형
- 압축파일: 파일 모양에 가로 줄무늬 세 개
- 잠금: 둥근 사각형과 위쪽 반원
- 성공(원 안의 체크), 경고(삼각형 안의 느낌표), 오류(원 안의 가위표)
- 끌어 놓기 영역 대표 아이콘은 48 크기의 압축파일 아이콘 하나

## 6. 화면 상태별 배치

창 제목은 압축파일을 열었으면 "압축파일 전체 경로 — Zipelo", 열지 않았으면 "Zipelo"다. 상단 툴바에 [열기] [압축하기] [압축해제]를 왼쪽부터 배치하며, 큰 아이콘 아래 글자를 붙인다. 작업 중에는 새 작업을 여는 툴바 버튼을 비활성화한다. 모달이 열려 있으면 배경 화면은 조작할 수 없다.

### 6.1 빈 화면

- 툴바 아래에 압축파일 끌어 놓기 영역과 "압축파일을 여기에 끌어 놓으세요", 지원 형식 안내를 보여 준다.
- [열기]는 운영체제 기본 파일 열기 창을 연다. 파일을 끌고 오면 영역을 강조하고 "놓으면 엽니다"를 보여 준다.
- [압축하기]는 운영체제 폴더 선택 창부터 열고, 유효한 폴더를 고르면 6.7 ZIP 만들기 창을 연다. 압축파일이 없으면 [압축해제]는 비활성이며 이유를 툴팁으로 알린다.
- 하단 상태 줄은 "0개 항목", "선택 0개"를 보여 준다.

### 6.2 압축파일 열림과 폴더 탐색

```
+--------------------------------------------------------------+
| 압축파일 전체 경로 — Zipelo                                  |
+--------------------------------------------------------------+
| [열기]       [압축하기]       [압축해제]                        |
+--------------------------------------------------------------+
| [위로] 현재 경로 [/Install              ] [파일 찾기       ] |
+--------------------------------------------------------------+
|     이름                                   크기     암호     |
|     (파일) cab1.cab                        94.9 MB           |
|     (파일) cab2.cab                        98.6 MB           |
|                                                              |
+--------------------------------------------------------------+
| 2개 항목                                          선택 0개   |
+--------------------------------------------------------------+
```

- 툴바 아래 경로 줄은 [위로], "현재 경로" 표시칸, "파일 찾기" 검색칸 순서다. 현재 경로는 압축파일 내부 경로이며 루트는 `/`, 하위 폴더는 `/Install`처럼 표시한다. 운영체제 파일 경로 입력칸이 아니다.
- 목록은 현재 폴더 바로 아래 항목만 보여 준다. 폴더를 열면 하위 목록으로 이동하고 [위로]는 부모로 이동한다. 루트에서는 [위로]를 비활성화한다. 검색은 현재 폴더 안의 이름을 거르며 하위 폴더 전체를 검색하지 않는다.
- 폴더 항목이 따로 없는 압축파일도 파일 경로에서 가상 폴더를 구성한다. 가상 폴더는 탐색용이며 작업자 요청에 가짜 ID를 넣지 않는다.
- 열은 이름, 크기, 암호 순서다. 행과 머리글의 선택 체크박스는 두지 않으며 선택한 행은 파란 배경으로 표시한다. 이름 앞에 폴더는 주황색 아이콘, 파일은 파일 아이콘을 둔다. 크기는 오른쪽 정렬, 암호가 있으면 잠금 아이콘과 "있음"을 표시한다. "형식"과 수정 날짜 열은 넣지 않는다.
- 목록은 창 너비와 남는 높이를 사용하며 세로 스크롤한다. 폴더 진입 동작과 행 선택 동작을 구분한다.
- 폴더를 선택하면 해당 폴더와 모든 하위 실제 항목을 추출 대상으로 확장한다. 부모 폴더와 자식 항목을 함께 선택해도 실제 ID는 중복 없이 한 번만 보낸다. 명시적인 빈 폴더 ID도 포함한다. 완료 판정은 이 확정된 요청 ID 집합과 동일한 범위를 사용한다.
- 하단 상태 줄 왼쪽은 현재 표시 목록의 "N개 항목", 오른쪽은 "선택 N개"를 보여 준다. 선택한 행 수를 표시하며 재귀 확장된 요청 ID 수를 표시하지 않는다. 예를 들어 파일 세 개가 든 폴더 하나를 선택하면 "선택 1개"다.
- [압축해제]는 6.8의 운영체제 기본 폴더 선택창을 연다. 기본 위치는 압축파일이 있는 폴더다. 선택 항목이 있으면 확장한 선택 범위를, 선택이 없으면 전체 압축파일을 대상으로 한다. 검색 결과나 현재 폴더만으로 추출 범위를 암묵적으로 줄이지 않는다.
- 풀 위치 선택을 확정한 뒤에만 요청을 보낸다. 취소하면 폴더 생성이나 추출을 시작하지 않는다. 앱이 새 출력 폴더를 만드는 경로는 Unix에서 umask와 무관하게 0700으로 생성한다. 기존 사용자 폴더 권한은 바꾸지 않는다.
- 폴더 생성에 실패하면 요청 없이 "풀 위치 폴더를 만들 수 없습니다. 접근 권한을 확인하세요"를 보여 주고 다시 폴더를 고르게 한다. 실패나 취소 뒤 앱이 이번 작업에서 만든 빈 폴더만 정리한다. 사용자 폴더와 비어 있지 않은 폴더는 지우지 않는다.
- 충돌은 일부 저장 후에도 생길 수 있으므로 실제 저장 결과에 따른 6.6과 7.3 안내를 유지한다. 기존 파일은 덮어쓰지 않는다.
- GZ 단일 파일은 폴더 선택창 대신 운영체제 기본 저장 창을 연다. 압축파일 이름에서 .gz를 뺀 출력 이름을 미리 채우고 사용자가 수정할 수 있게 한다. 제안할 이름이 비었거나 쓸 수 없는 문자를 포함하면 안전한 기본 이름으로 바꾼다.
- GZ 저장 경로에 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 저장 창을 다시 열어 다른 이름이나 위치를 고르게 한다. 충돌한 경로로 추출을 시작하지 않으며, 재선택 창을 취소해도 추출하지 않는다.
- 비어 있는 압축파일은 "이 압축파일은 비어 있습니다", 검색 결과가 없으면 "일치하는 항목이 없습니다"를 표시한다.

### 6.2.1 탐색기 방식 목록 선택

- 클릭하면 해당 항목 하나만 선택한다. Ctrl+클릭은 해당 항목을 기존 선택에 추가하거나 선택에서 뺀다. Shift+클릭은 마지막으로 고른 기준 항목부터 클릭한 항목까지 현재 표시 순서의 연속 범위를 선택한다.
- 목록의 빈 곳을 클릭하면 선택을 해제한다. 빈 곳에서 마우스를 누른 채 끌면 반투명한 파란 면과 1px 진한 파란 테두리로 선택 사각형을 표시하고, 사각형에 걸친 파일과 폴더를 선택한다. 사각형 아래 파일 이름과 크기가 비쳐 보여 읽을 수 있어야 한다. Ctrl을 누른 채 끌면 기존 선택에 해당 범위를 더한다.
- 끌기 중 포인터가 목록의 위나 아래 끝에 닿으면 자동으로 스크롤하며 새로 사각형에 걸친 항목도 선택한다. 마우스를 놓으면 사각형을 없애고 선택은 유지한다. 외부 파일 끌어 놓기와 목록 안의 선택용 끌기를 구분한다.
- 폴더를 더블클릭하면 안으로 들어간다. 파일 더블클릭은 선택만 하며 미리보기나 외부 프로그램 실행, 압축해제를 시작하지 않는다.
- 목록에 초점이 있을 때 위아래 화살표는 항목을 이동하며 선택하고, Shift+위아래 화살표는 기준 항목부터 이동한 항목까지 범위를 선택한다. Ctrl+A는 현재 표시 목록 전체를 선택하고 Esc는 선택을 해제한다.
- 목록의 Enter는 초점이 있는 폴더 안으로 들어가며 Backspace는 상위 폴더로 이동한다. 루트의 Backspace는 이동하지 않는다. 이 키 입력으로 ZIP 생성이나 추출을 함께 시작하지 않는다.
- 목록 키보드 동작은 검색칸이나 다른 입력칸의 편집, 초점이 있는 버튼의 Enter 동작, 모달의 입력과 취소 동작을 가로채지 않는다. 모달이 열린 동안 배경 목록을 조작하지 않는다.
- 폴더 이동과 검색 변경 뒤 이전 행 번호를 다른 항목의 선택으로 재사용하지 않는다. 표시된 선택과 상태 줄의 선택 수, 실제 추출 대상이 일치해야 한다. 선택이 없을 때 전체 압축파일을 추출한다는 6.2의 규칙은 그대로 적용한다.

### 6.3 암호 입력

모달 창, 너비 420, 화면 가운데. 현재 지원하는 암호 ZIP은 목록을 읽을 때 암호를 묻지 않는다. 사용자가 [압축해제]를 눌러 추출을 시작한 뒤 작업자가 암호를 요청할 때 이 창을 연다. 암호 ZIP을 여는 것만으로는 띄우지 않는다.

```
+------------------------------------------+
| 암호가 필요합니다                        |
| sample.zip은 암호로 보호되어 있습니다.   |
|                                          |
| 암호  [**********************]  [보기]   |
|                                          |
|                     [취소]  [ 확인 ]     |
+------------------------------------------+
```

- 창이 열리면 암호 입력칸에 초점이 있다. 암호 입력칸에서 Enter를 누르면 화면의 입력 조건을 충족한 암호를 제출한다. 버튼에 초점이 있으면 Enter는 그 버튼만 실행한다([취소]에서는 제출하지 않는다). Esc는 취소다.
- 암호를 틀린 뒤 다시 열린 창에는 입력칸 아래에 오류색으로 "암호가 맞지 않습니다. 다시 입력하세요"를 보여 준다. 입력칸은 비우고 초점을 둔다.
- [보기]는 입력 내용을 보이거나 숨기는 토글이다. 기본은 숨김이다.
- [확인]이 주 버튼이다. 입력이 비어 있으면 비활성이다.

### 6.4 진행 중

진행 상태는 메인 창 아래에 붙이지 않고 별도 작업 창으로 표시한다. 목록과 상태 줄은 메인 창에 남으며 작업 중 선택 변경은 막는다.

- 별도 작업 창은 처음에 부모 창 가운데에 열리고, 사용자가 옮긴 상대 위치를 기억해 부모 이동을 따른다. 위치를 지정할 수 없는 환경은 창 관리자 배치를 따른다. 앱이나 자식 창에 초점이 있을 때만 위에 두며 다른 앱을 가리지 않는다.
- 메인 모달 상태(암호 입력, 종료 확인, 파일 선택 대기 안내)나 ZIP 만들기가 열리면 진행/결과 창을 닫아 입력과 버튼을 가리지 않는다. 모달이 해제되고 표시할 진행이나 결과가 남아 있으면 기억한 위치에 다시 연다. 작업 자체를 취소하거나 결과를 삭제하는 동작은 아니다.
- 별도 창을 만들 수 없는 환경에서는 메인 목록 아래의 하단 영역으로 대체한다. 이 대체 배치를 일반 데스크톱의 별도 창 동작과 혼동하지 않는다.

```
| 압축을 푸는 중                                               |
| [=========================------------------]  62%           |
| 12개 처리함, 38 MB / 61 MB                       [ 취소 ]    |
```

- 제목은 단계 문구를 쓴다(7장). 진행 막대는 전체 크기를 알 수 있으면 비율로, 알 수 없으면 옅은 파란색으로 채운 정적인 막대로 보여 준다. 알 수 없는 상태에서 퍼센트를 지어내지 않는다.
- [취소]는 위험 버튼 모양이다. 누르면 문구가 "취소하는 중..."으로 바뀌고 버튼은 비활성이 된다.
- 작업 중 메인 창 닫기는 6.9의 확인 절차를 따른다. 진행 창 자체의 닫기 버튼으로는 작업을 종료하지 않으며 창 닫기를 막는다. 작업 취소는 [취소]를 사용한다. 읽기 단계는 처리 항목 수 없이 읽은 용량을 표시한다.

### 6.5 완료

별도 작업 창의 내용이 결과 알림 상자로 바뀌고 제목은 "작업 결과 — Zipelo"가 된다. 메인 창의 목록과 상태 줄은 유지한다.

```
| (성공 아이콘) 압축을 풀었습니다                              |
| D:\받은파일\sample 폴더에 저장했습니다.                      |
|                                  [폴더 열기]  [ 확인 ]       |
```

- 성공 알림 상자는 연한 녹색 배경에 녹색 아이콘이다. [폴더 열기]가 주 버튼이고 [확인]은 보조 버튼이다. [확인] 또는 결과 창의 닫기 버튼을 누르면 결과 창을 닫고 메인 목록을 유지한다.
- [폴더 열기]는 운영체제 파일 탐색기를 연다(Windows는 explorer, Ubuntu는 xdg-open, 경로는 셸을 거치지 않고 인자로 전달한다).
- 완료 판정과 저장 확인(내구성) 안내는 별도로 다룬다. Outcome::Completed에 Durability::Unconfirmed가 함께 와도 완료 안내와 [폴더 열기]를 유지하며, 저장 미확인 안내는 "자세히 보기" 안에만 둔다. 실패나 일부 추출의 경고 표시는 7.3을 따른다. 정상 결과에는 내부 상태 줄을 붙이지 않는다.
- ZIP 만들기 완료도 같은 모양이다. 제목은 "ZIP 파일을 만들었습니다", 본문은 저장한 파일의 전체 경로다.
- 취소로 끝났을 때는 회색 알림 상자에 "작업을 취소했습니다"를 보여 준다. 일부 파일이 남았다면 7.3 경고를 함께 보여 준다.

### 6.6 오류

완료와 같은 별도 작업 창에 오류 알림 상자를 둔다. 연한 빨간 배경, 오류 아이콘.

```
| (오류 아이콘) 압축을 풀지 못했습니다                         |
| 디스크 여유 공간이 부족합니다. 공간을 확보한 뒤 다시         |
| 시도하세요.                                                  |
| [자세히 보기]                      [다시 시도]  [ 확인 ]     |
```

- 제목은 하는 일에 따라 "압축을 풀지 못했습니다", "압축파일을 열지 못했습니다", "ZIP 파일을 만들지 못했습니다"를 쓴다. 본문은 7.1의 오류 문구다.
- [다시 시도]가 주 버튼이다. 같은 요청을 다시 보낸다. 암호 ZIP 생성 재시도는 암호를 보관하지 않으므로 ZIP 만들기 창에서 다시 입력받고 저장 위치를 확정한다. 오류가 "원본 파일이 바뀌었습니다" 종류이면 [다시 시도] 대신 [압축파일 다시 열기]를 보여 준다.
- [자세히 보기]를 누르면 7.2의 내부 상태 줄을 연한 회색 상자에 펼친다. 기본은 접혀 있다.
- 같은 이름의 파일이 이미 있어 중단된 경우(충돌)에는 [다시 시도] 대신 [다른 폴더에 풀기]가 주 버튼이다. 본문은 "같은 이름의 파일이 이미 있습니다. 다른 폴더를 선택하세요"이며, 저장 결과는 7.3의 기준에 따라 별도로 안내한다. 누르면 6.8의 폴더 선택창이 열리고, 사용자가 폴더를 고르면 같은 선택 항목으로 다시 요청한다. 저장 여부가 불확실하면 먼저 기존 풀 위치를 확인하도록 경고하고, 확인과 사용자 선택 없이 자동으로 재요청하지 않는다. 이미 저장된 파일과 기존 파일은 지우거나 덮어쓰지 않는다. [확인]은 보조 버튼으로 6.2로 돌아간다.
- 단일 파일 GZ 충돌은 예외다. [다른 폴더에 풀기] 대신 [다른 이름으로 저장]을 제공하고, "같은 이름의 파일이 이미 있습니다. 다른 이름이나 저장 위치를 선택하세요"를 보여 준다. 폴더 선택창 대신 6.2의 운영체제 저장 창을 다시 열어 이름과 위치를 수정하게 한다. 유효한 새 저장 경로를 확정한 뒤에만 다시 요청하며, 취소하면 재요청하지 않는다. 기존 파일 보존과 저장 결과별 경고는 위와 같다.

### 6.7 ZIP 만들기 창

첫 화면과 압축파일을 연 화면에서 툴바의 [압축하기]를 누르면 운영체제 폴더 선택 창이 먼저 열린다. 유효한 폴더를 고른 뒤 "ZIP 만들기 — Zipelo"라는 별도 창을 연다. 이미 ZIP 만들기가 열린 상태에서 다시 폴더를 고르다가 취소하면 기존 원본 목록과 암호 설정을 유지한다. 새 폴더를 유효하게 선택했을 때만 원본과 암호 설정을 초기화한다.

```
+----------------------------------------------------------+
| ZIP 만들기                                          [X]  |
| [위로] [/photos                                     ]   |
| +----------------------------------------------------+   |
| | (폴더) 여행                                        |   |
| | (파일) photo.jpg                         2 MB       |   |
| +----------------------------------------------------+   |
| [x] 암호로 보호하기                                      |
| 암호       [***********************] [보기]              |
| 암호 확인  [***********************]                     |
| 암호를 잊으면 파일을 열 수 없습니다.                    |
|                                  [취소] [압축하기]      |
+----------------------------------------------------------+
```

- 창 너비는 560이며 높이는 내용에 맞춘다. [취소]와 [압축하기]는 오른쪽 아래에 고정한다. 별도 창을 만들 수 없는 환경에서는 같은 내용을 메인 창의 모달에 표시한다.
- 상단에 [위로]와 현재 경로를 두고, 아래 목록은 파일/폴더 아이콘, 이름과 크기를 표시한다. 폴더 하나를 고른 경우 그 내부를 보여 주며 폴더 더블클릭과 [위로]로 탐색한다. 빈 폴더와 읽기 실패 안내를 구분한다. 행 클릭의 선택 표시는 내용을 확인하기 위한 것이며, 하위 폴더로 이동하거나 행을 선택해도 압축 원본 범위를 줄이지 않는다. 선택한 원본 폴더 전체를 묶는다.
- 이전 점선 파일 추가 영역, [폴더 추가], [빼기], 압축 방식의 접힌 설정은 이 창에 표시하지 않는다. 여러 원본이 입력된 경우에는 해당 원본 목록을 표시한다. 기본 압축 방식은 Deflate다.
- 경로 입력에 기존 안전성 검증을 적용한다. 접근할 수 없는 경로, 지원하지 않는 파일 종류와 안전하지 않은 경로는 설명과 함께 거부하며 작업자의 경로 안전성 검증을 유지한다.
- "암호로 보호하기"를 켜면 같은 창의 체크박스 아래에 암호, 암호 확인과 [보기]/[숨기기]를 표시한다. 기본은 숨김이다. 암호가 비었거나 두 값이 다르거나 UTF-8 1024바이트를 넘으면 [압축하기]는 비활성이다. 불일치 또는 길이 초과 안내와 "암호를 잊으면 파일을 열 수 없습니다."를 표시한다.
- 보호 옵션을 끄거나 ZIP 창을 닫으면 입력한 암호와 실행 취소 기록을 비운다. 다시 켠 뒤 Ctrl+Z로 이전 암호를 복원할 수 없어야 한다. 암호 생성은 이 창에서 미리 받은 값을 작업자가 요청할 때 전달하므로 정상 흐름에서 별도 암호 설정 모달을 다시 띄우지 않는다. 추출 암호 요청은 6.3을 따른다.
- 원본이 없거나 암호 조건이 맞지 않으면 [압축하기]는 비활성이다. 활성 버튼을 누르면 운영체제 저장 창에서 위치와 이름을 고른다. 첫 원본 이름을 기준으로 .zip 이름과 부모 폴더를 제안하며 기존 파일을 덮어쓰지 않는다.
- 저장 위치 선택 대기 중에는 ZIP 창의 내용과 실행 버튼을 비활성화한다. 저장 창을 취소하면 생성하지 않는다. 그 사이 ZIP 창의 [X]로 닫았다면 늦게 도착한 저장 확정 응답으로도 생성하지 않는다. [취소]도 창을 닫고 암호를 지우며, 모달 대체 배치에서는 Esc로도 닫을 수 있다.
- 유효한 저장 위치를 확정하고 생성이 시작되면 ZIP 만들기 창을 닫고 6.4의 진행 창을 보여 준다. 빈 화면에서 시작해도 같은 진행과 결과 규칙을 적용한다.

### 6.8 운영체제 기본 파일과 폴더 대화창

앱 안 파일 선택기는 제거한다. rfd는 `default-features = false`로 사용하고 Windows는 기본 백엔드, Linux는 GTK 없이 `xdg-portal`을 사용한다. rfd 및 전이 의존성의 라이선스 고지는 `packaging/licenses.py`로 갱신한다.

- [열기]: 압축파일을 고르는 운영체제 기본 파일 열기 창. 지원 확장자의 대소문자 변형도 필터에 포함하고 "모든 파일" 선택지를 둔다. sample.ZIP과 sample.Zip도 선택할 수 있어야 한다.
- 툴바 [압축하기]: 원본 폴더를 고르는 운영체제 기본 폴더 선택 창. 선택 성공 후 ZIP 만들기 창을 연다.
- ZIP 저장: .zip 기본 이름을 제안하는 운영체제 기본 저장 창.
- 압축해제 위치: 압축파일의 부모 폴더를 기본 위치로 여는 운영체제 기본 폴더 선택 창. 단일 파일의 저장 경로 선택도 운영체제 기본 저장 창을 사용한다.
- 대화창 취소는 결과 없음으로 처리한다. 열기 취소는 현재 압축파일을 유지하고, 원본 폴더 선택 취소는 기존 ZIP 원본 목록과 암호 설정을 유지하며, 출력 위치 취소는 작업을 시작하지 않는다. 이전 대화창 결과를 재사용해 실행하지 않는다.
- 사용자 취소와 대화창 실행 실패를 구분한다. 취소는 오류로 표시하지 않지만, Linux portal 없음이나 백엔드 오류로 창을 띄우지 못하면 알림 상자에 해당 선택 창을 열 수 없다는 안내를 보여 준다. 두 경우 모두 작업 요청이나 파일 생성을 하지 않고 기존 상태를 유지한다. 앱 안 선택기로 조용히 대체하지 않는다.
- 열기 실패에서는 "파일 선택 창을 열 수 없습니다. 파일을 창으로 끌어 놓아 주세요."처럼 사용 가능한 다음 행동을 안내한다. ZIP 원본 폴더 선택은 폴더 선택 창, ZIP 저장과 GZ 저장은 저장 창, 추출 위치 선택은 폴더 선택 창의 실패임을 알린다. 저장 위치 선택 실패에 입력 파일 끌어 놓기를 해결 방법으로 안내하지 않는다.
- 운영체제 대화창 내부의 키보드 동작은 운영체제 표준을 따른다. 닫힌 뒤 입력을 앱에 중복 전달해 생성이나 추출을 시작하지 않는다.

### 6.9 메인 창 닫기

- 실행 중인 작업이 없으면 결과 확인 안내 없이 즉시 닫는다. 이전 작업 결과가 남아 있어도 추가 확인을 요구하지 않는다.
- 작업 중에는 "작업을 취소하고 닫을까요?"와 [계속 작업], [취소하고 닫기]를 표시한다. 승인 전에는 종료하지 않는다.
- 확인에 답하기 전에 작업이 끝나도 자동으로 닫지 않는다. "작업이 끝났습니다. 창을 닫을까요?"와 [열어 두기], [닫기]로 바꾸고 응답을 기다린다.
- [취소하고 닫기]를 승인하면 취소와 정리가 끝나기를 기다린 뒤 추가 결과 확인 없이 닫는다. 기다리는 동안 [닫기 취소]로 종료를 철회할 수 있다.

## 7. 문구

### 7.3 결과 상태별 저장 안내와 경고

저장 결과는 오류 코드와 별도로 판단한다. Conflict와 UnsafePath도 같은 기준을 따른다. 정상적으로 수집한 최종 결과에서 Publication::None, created_count=0, retained_partial_count=0, Cleanup::Complete가 확인되고, 출력 보고와 종료 확인에 누락이나 모순이 없을 때만 "아무 파일도 풀지 않았습니다" 또는 "파일은 저장하지 않았습니다"를 보여 준다. 생성 수가 0이라는 사실이나 오류 코드만으로는 이 문구를 쓰지 않는다. 최종 결과가 없거나 신뢰할 수 없으면 저장 여부 불확실 안내를 쓴다.

결과가 아래에 해당하면 완료 또는 오류 알림 상자 안에 경고(주황) 줄을 함께 보여 준다. 단, Outcome::Completed인 결과의 Durability::Unconfirmed 안내는 "자세히 보기" 안에만 표시하고 완료 안내와 [폴더 열기]를 유지한다. 이 저장 미확인 상태만으로 실패나 재시도로 바꾸지 않는다. 결과가 실패하거나 일부만 풀린 경우에는 저장 미확인 경고를 알림 상자에 바로 표시한다. 이 예외는 Durability::Unconfirmed에만 적용하며, CommitUncertain 또는 Publication::Uncertain의 저장 여부 불확실, 동기화 실패와 임시 파일 정리 경고를 숨기는 근거로 쓰지 않는다. 바로 표시해야 하는 경고를 미저장 안내로 대체하지 않는다.

- 실제 일부 추출: 요청에서 확정한 대상 파일 중 일부의 Created 보고만 확인되고 나머지가 저장되지 않은 것이 확인되면 "일부 파일만 풀렸습니다. 풀린 파일은 풀 위치 폴더에 남아 있습니다."를 보여 준다. PartialRetained는 임시 파일 잔존 보고이므로 이 판정의 근거로 쓰지 않는다. Publication::Partial이나 created_count만으로도 판정하지 않는다(생성 수에는 폴더가 포함될 수 있다).
- 전체 파일 저장 후 임시 파일 잔존: 대상 파일이 하나 이상이고 대상 파일 전체의 Created 보고가 확인되고 저장 여부에 불확실성이 없는데 PartialRetained 또는 retained_partial_count로 임시 파일 잔존이 확인되면 "선택한 파일은 모두 저장했지만 임시 파일을 지우지 못했습니다. 풀 위치 폴더를 확인하세요."를 보여 준다. 마지막 파일 저장 후 정리에 실패하면 Outcome::Failed와 Publication::Partial일 수 있으므로 Completed나 Complete만을 조건으로 삼지 않는다. 작업 전체를 정상 완료로 표시하지 않고, 동기화 경고가 있으면 함께 보여 준다.
- 저장 여부 불확실(CommitUncertain, 게시 불확실): "저장이 끝났는지 확인하지 못했습니다. 풀 위치 폴더를 확인하세요."
- 디스크 동기화 실패 또는 미확인: "파일을 디스크에 완전히 저장했는지 확인하지 못했습니다." Durability::Unconfirmed는 완료 결과에서는 "자세히 보기" 안의 보조 안내로, 실패 또는 일부 추출 결과에서는 알림 상자의 경고로 표시한다. Durability::Failed는 결과와 관계없이 경고를 바로 표시한다.
- 임시 파일 정리 실패 또는 미확인: "임시 파일을 지우지 못했습니다. 풀 위치 폴더에 남은 임시 파일이 있을 수 있습니다." 전체 파일 저장 후 임시 파일 잔존 안내를 이미 보여 줬으면 같은 경고를 반복하지 않는다. 일부 추출과 임시 파일 잔존이 함께 확인되면 두 사실을 모두 안내한다.

대상 파일과 Created 보고를 대조할 수 없거나 최종 결과와 모순되면 일부 또는 전체 추출을 단정하지 않고 저장 여부 불확실 안내를 우선한다. PartialRetained만 받은 경우에도 추출 완료 여부를 추정하지 않는다. 기존 결과와 임시 파일은 이 안내를 근거로 자동 삭제하지 않는다.

## 8. 접근성과 키보드

- eframe의 accesskit 기능은 이미 켜져 있다. 목록 항목과 선택 상태, ZIP 암호 설정 체크박스, 버튼, 입력칸에 한국어 이름과 상태가 읽히도록 레이블을 단다. 아이콘만 있는 요소에는 hover 텍스트와 접근성 이름을 단다.
- 모든 기능을 키보드로 쓸 수 있다. 다음 Enter 규칙은 앱 내부에 적용하며 운영체제 대화창은 6.8을 따른다. Tab 순서는 화면 위에서 아래, 왼쪽에서 오른쪽이다. Enter는 초점이 있는 활성 버튼만 실행하며, 화면의 주 버튼을 대신 실행하지 않는다. 버튼에 초점이 없거나 버튼이 비활성이면 Enter로 버튼 동작을 실행하지 않는다. 목록 초점에서는 6.2.1의 폴더 이동 Enter와 선택 해제 Esc를 적용하고, 암호 모달과 ZIP 만들기의 모달 대체 배치에서는 Esc로 취소한다.
- 유일한 제출 예외는 별도 암호 요청 모달의 입력란이다. 이 입력란에 초점이 있을 때 Enter로 화면의 입력 조건을 충족한 암호를 제출할 수 있다. ZIP 만들기의 암호 칸은 6.7에서 입력만 받고 [압축하기] 버튼으로 저장 창을 연다. 별도 암호 요청 모달에서 생성 암호를 제출하는 경우에는 암호 확인까지 일치해야 한다. 다른 입력란에는 이 예외를 적용하지 않는다. [취소] 등 보조 버튼에 초점이 있으면 해당 버튼만 실행하고 암호 제출, ZIP 생성이나 추출을 함께 시작하지 않는다. 같은 Enter 입력으로 두 동작을 실행하지 않는다.
- 색만으로 상태를 전하지 않는다. 성공, 경고, 오류는 아이콘과 제목 문구를 함께 쓴다.
- 메인 창 크기를 줄여도(최소 760x540) 글자가 잘리거나 버튼이 겹치지 않는다. 긴 파일 이름은 가운데를 줄임표로 줄이고 전체 이름은 hover로 보여 준다.

## 9. 구현 메모

- 화면 구성 코드는 archive_screen.rs와 archive_ui.rs의 표시용 함수에 모은다. 문구 변환(오류 코드에서 문구, 단계에서 문구, 경고 판정)은 화면을 그리지 않는 순수 함수로 만들어 tests/에서 단위 시험한다.
- 색과 간격은 한 곳(상수 모듈)에 둔다. 화면 코드에 색 값을 직접 쓰지 않는다.
- 작업자 계약 revision 2의 필드와 태그는 바꾸지 않는다. 폴더 탐색과 선택 확장은 앱에서 처리하며 기존 실제 항목 ID로 요청한다. 완료 판정은 송신한 ID 집합을 사용한다.

## 10. 수용 기준

각 항목은 Xvfb 스크린샷 또는 tests/ 아래 시험으로 확인한다. 운영체제 기본 대화창은 Windows와 Linux portal 환경에서 별도 실행 확인하며 스크린샷만으로 동작 통과를 선언하지 않는다.

1. 빈 화면에도 세 툴바 버튼과 상태 줄이 보인다. 압축파일이 없을 때 압축해제는 비활성이며, 열기와 압축하기는 사용할 수 있다.
2. 파일을 창 위로 끌면 영역이 강조색으로 바뀌고 "놓으면 엽니다"가 보인다.
3. 창 제목에 압축파일 전체 경로와 Zipelo가 표시된다. 목록은 행과 머리글의 선택 체크박스 없이 이름, 크기, 암호 열로 현재 폴더의 바로 아래 항목만 표시하며 폴더 아이콘은 주황색이다.
4. 툴바에 큰 아이콘과 글자의 [열기] [압축하기] [압축해제]가 순서대로 보인다. 경로 줄과 검색, 하단 항목 수와 선택 수가 시안과 같은 위치에 있다.
5. 압축해제는 압축파일 옆을 기본 위치로 하는 운영체제 폴더 선택창을 열고, 확정 후에만 요청한다. GZ 단일 파일은 운영체제 저장 창에 출력 이름을 미리 채우고 사용자가 수정할 수 있다. .gz와 report:2026.gz에서 빈 이름과 사용할 수 없는 문자를 안전한 기본 이름으로 보정하고, 수정한 유효한 이름으로 추출되는지 실제 작업자 연동 회귀 시험으로 확인한다. 같은 이름의 파일이 있으면 기존 내용을 보존하고 저장 창을 다시 열며, 다른 경로를 확정해야 추출한다. 충돌 후 재선택과 취소도 회귀 시험에 포함한다.
6. 파일 열기 필터는 지원 확장자의 대소문자 변형을 포함하고 "모든 파일" 선택지를 제공한다. sample.ZIP과 sample.Zip을 선택할 수 있는지 필터 단위 회귀 시험과 Linux 기본 대화창에서 확인한다. 열기, ZIP 원본 폴더 선택, ZIP 저장 및 추출 위치 선택이 모두 운영체제 기본 대화창을 사용한다. 취소와 대화창 오류에서 요청과 파일 생성이 없고 기존 상태를 유지한다. 앱 안 선택기로 대체하지 않는다.
7. 폴더 선택 시 모든 하위 실제 ID를 포함하고 중복을 제거한다. 명시적 빈 폴더와 가상 폴더, 부모와 자식 중복 선택을 시험한다. 완료 판정의 대상 집합이 실제 요청과 일치한다. 선택이 없으면 전체 추출하며 검색 결과만으로 범위를 줄이지 않는다.
8. 정상 완료 화면에 "게시된 파일", "동기화", "임시 파일 N개" 같은 내부 문구가 없다. "자세히 보기"를 눌러야 보인다.
9. 7.3의 결과 상태별 표시 규칙을 따른다. tests/의 화면 시험에서 "완료 + 저장 미확인"은 완료 안내와 [폴더 열기]를 유지하고 저장 미확인 문구가 기본 화면에는 없으며 "자세히 보기"를 펼치면 보이는지 확인한다. "실패 + 저장 미확인"과 "일부만 풀림 + 저장 미확인"은 자세히 보기를 펼치지 않아도 해당 경고가 보이는지 각각 확인한다. 세 조합의 저장 미확인은 Durability::Unconfirmed이며, CommitUncertain 또는 Publication::Uncertain과 혼동하지 않는다. tests/의 문구 판정 시험은 최소한 다음 입력을 구분한다: 대상 파일 2개 중 Created 1개와 미저장 1개 확인 시 일부 추출 안내, 대상 파일 1개의 Created와 PartialRetained가 함께 있고 Outcome::Failed, Publication::Partial, created_count=1, retained_partial_count=1, Durability::Synced, Cleanup::Failed인 경우 전체 파일 저장 후 임시 파일 잔존 안내. 후자를 "일부 파일만 풀렸습니다"나 정상 완료로 표시하지 않는다. PartialRetained만 있고 대상 파일 저장 결과를 확인할 수 없는 경우와 CommitUncertain이 함께 있는 경우에는 저장 여부 불확실 안내를 확인한다. 동기화와 정리 경고의 동시 표시도 검증한다.
10. 모든 오류 코드가 7.1의 문구로 바뀌어 보인다. 내부 오류 묶음은 "내부 오류가 발생했습니다. 프로그램을 다시 시작해 주세요"로 보인다. UnsafePath는 오류 코드만으로 미저장을 단정하지 않고, 미저장 확인, 일부 저장, 저장 여부 불확실 결과를 각각 7.3에 따라 안내한다(시험: 오류 코드 전체에 대한 문구 매핑과 UnsafePath의 저장 결과별 판정).

35. 전체 UI의 표시와 상호작용에 fade-in, fade-out, 색 보간, 움직이는 불확정 진행 표시가 없고 결과가 즉시 반영되는지 확인한다. 실제 작업 진행 값의 갱신은 유지한다.

## 11. 결정 상태

1. 기본 대화창(결정됨): 이준영 님의 2026-11-12 요청에 따라 파일과 폴더 및 저장 위치는 운영체제 기본 대화창을 쓴다. 총관리자는 rfd를 예외 라이브러리로 정하고 Linux는 xdg-portal, Windows는 기본 백엔드를 사용하도록 지정했다.
2. 폴더 선택(결정됨): 압축파일 내부 폴더 선택은 하위 실제 항목 전체로 확장하고, 요청과 완료 판정에 같은 ID 집합을 사용한다. 가상 폴더를 위한 계약 변경은 하지 않는다.
3. 기존 압축파일 재암호화(제외): 이준영 님의 2026-11-12 정정에 따라 기존 압축파일에 암호를 다시 거는 기능은 v0.1에서 제외한다. 툴바의 [암호화] 버튼은 넣지 않으며, 새 ZIP의 암호 설정은 ZIP 만들기 창의 "암호로 보호하기"로 유지한다.
4. 폴더 생성과 결과 안전성(유지): 앱의 새 출력 폴더 0700 생성, 기존 파일 덮어쓰기 금지, 7.3 경고와 확정된 요청 범위의 완료 판정은 유지한다.
5. 목록 선택(결정됨): 이준영 님의 2026-11-12 요청에 따라 목록 선택 체크박스를 없애고 클릭, Ctrl, Shift, 빈 곳에서 끌기와 키보드를 사용하는 탐색기 방식으로 전환한다. 선택 사각형은 이준영 님의 2026-11-12 정정에 따라 바탕화면처럼 반투명한 파란 면과 진한 파란 테두리로 표시하며 아래 항목이 보이게 한다.
6. 수정 날짜 열(유지): v0.1에서 넣지 않는다. 계약 변경이 필요하므로 다음 버전에서 다룬다.

## 12. 범위 밖

다크 모드, 설정 화면, 미리보기, 최근 연 파일 목록, 언어 선택, 화면 크기에 따른 글자 크기 조절, 기존 압축파일 재암호화는 v0.1 이후에 다룬다.

## 공통 응용 프로그램 아이콘

모든 Zipelo 플랫폼과 후속 응용 프로그램은 `experiments/rust-ui-memory-app/src/assets/icons/zipelo.png`를 공통 원본으로 사용한다. 사용자가 제공한 원본의 모양과 투명도를 유지하며 별도 디자인으로 대체하지 않는다.

- `zipelo-256.png`: 실행 창과 Ubuntu의 hicolor 앱 아이콘이다.
- `zipelo.ico`: Windows 실행 파일, 설치 및 제거 프로그램의 아이콘이다. 16, 24, 32, 48, 64, 128, 256픽셀을 포함한다.
- 파생 파일은 공통 PNG에서 Lanczos 축소로 만든다. 새 플랫폼의 아이콘 형식도 같은 원본에서 변환한다.
